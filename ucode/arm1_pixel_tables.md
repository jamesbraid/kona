## Converter lists

**Established** (the layout, every word below). A converter list is a run of 32-bit words, split into groups by bit 30, which is set on the last word of each group. Each word carries a field width in bits 16-23 and a bit position in bits 8-13; some carry the width again in the low byte, and some set bit 25. No list sets any other bit. The firmware writes a list to engine control memory when it sets up the output module whose record names the list's group ([below](#output-module-records)). **Inferred** (the role): each word tells the engine's output module where one component goes in a 64-bit output word, its width at its position; the lists for RGB5A1 give exactly 5-5-5-1 and those for R5G6B5 5-6-5, and a width of 0 is an empty slot that adds no data. Bit 25 is set in the lists the float and short-source paths use. The columns: the word count the group gives, the number of groups and the words in one, whether every group repeats the first, the distinct widths, the highest bit position, the bits one group fills, and counts of empty fields, bit-25 words and words whose low byte repeats the width.

## Converter groups

**Established** (every group below). A converter group is two words: a word count and a pointer to a converter list. The record that uses a group names it in its sixth word (word 5 from zero): the single output-module records [below](#output-module-records) and the record tables `RGBAoutputModuleTable`, `OneCmpntoutputModuleTable`, `ShortCircuitOutput`, `BitmapOutput` and `CIoutputModuleTable`, whose entries are seven words, so a table entry k names its group at word 7k + 5. The "named by" column gives the first record that holds the group's address and the word it sits in; the count after it is how many words of the image hold that address. When the first holder is a routine (`X_PixSetupGE` for the X server's pixel groups), the word is a literal-pool word counted from the routine's start, the place the routine loads the group's address from.

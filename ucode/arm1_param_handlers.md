## Light and user-clip-plane enable and disable handlers

**Established** (each body). `glEnable` and `glDisable` of `GL_LIGHTi` and `GL_CLIP_PLANEi` reach one of these leaf functions. Each writes a flag byte in the state block (r8), sends the light number or the plane enum (0x3000 + i) to port r9 + 0x478, for a light also sends the engine-memory address of that light's parameter block to port r9 + 0x840, and then sends half of a state word to port r9 + 0x8c0, the engine handler that applies the change. The light blocks are 0x23 words apart from 0x2c7. The disable handlers of the clip planes write the low byte of the state-block pointer r8 (shown as r8) as the flag instead of a constant 0. **Inferred:** that byte is 0. The reset and exception entries load r8 with 0 (`mov r8, #0x0` at 0x0c000000 and eight more), and the state-block offsets in every handler are taken from that base, so the flag is cleared as in the light handlers. **Established** (the engine routine started): the slot named by the half-word sent to port r9 + 0x8c0 is `mgeb_LiEnableLightS` for a light enable (low half of the word at r8 + 0x78, entry 51 of [geif_entries.md](geif_entries.md)), `mgeb_LiDisableLightS` for a light disable (high half of r8 + 0x74, entry 45), `mgeb_EnableUserClipPlane` for a plane enable (low half of r8 + 0x58, entry 19) and `mgeb_DisableUserClipPlane` for a plane disable (high half of r8 + 0x50, entry 9); the labels come from the shipped label table. **Inferred:** the Effect column and the Engine target column, from the instruction words of the four engine routines in [ge_compute.md](ge_compute.md). The plane routines store a flag pattern at the plane flag word (0x904 plus the enum less 0x3000) and go on to the clip-state rebuild; plane n is the number sent to port r9 + 0x478 and the Engine target of a plane is that flag word. The light routines never read the light number: they read only the second command word, the block address 0x2c7 + 0x23 n sent to port r9 + 0x840 (`mgeb_LiEnableLightS` 0xdd3e, `mgeb_LiDisableLightS` 0xdcc0). Control word 0x87 is a count of enabled lights, not a bit set: each routine converts the constant register 0x1f (1.0) to the integer 1 and adds it to, or subtracts it from, the word (0xdd5e and 0xdd62; 0xdcc4 and 0xdcc8). The enable stores the new count in word 0 of the light's block (0xdd6c) and the disable stores 0 there (0xdd07). Both store only under a predicate on special register 0x2e, which receives block word 0 (0xdd52, 0xdcd5): the disable acts under code 0x7c and the enable under its inverse 0x7d, so an enable of a light already on, or a disable of one already off, leaves the count alone. The Engine target of a light is that block word.

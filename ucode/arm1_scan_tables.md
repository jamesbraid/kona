# Boundary-scan chip types, element lists and chain records

Generated by `retools/tools/kona/arm1_scan_tables.py` from `ucode/KONA/arm1.u` (IRIX 6.5.30m) and [arm1_symbols.tsv](arm1_symbols.tsv); do not edit by hand. Every value is read from the image, and the script stops if a record breaks the shape below. The routines that walk these records (`jt_select_chip`, `chip_id`, the board probes) are in [arm1_functions.md](arm1_functions.md#boundary-scan-boards-and-serial-numbers).

## Chip types

**Established** (every record below). A chip-type description is twenty words: the chip code, a flag word (1 for the chips that use the shared instruction-code list `kona_jtag_ivalues`, 0 for the two that do not), the instruction-register width in bits, the pointer to that code list (0 when there is none) and sixteen data-register lengths in bits, one per instruction number 0-15. `jt_select_chip` puts the code for the chosen instruction number into the addressed chip's instruction register and adds that number's length to the running data-vector offset; every other chip gets the bypass code 0xff, number 15, whose length is 1 in every record. `chip_id` reads with instruction number 5, which selects a 32-bit register in every chip that has a code list. The table gives the lengths of numbers 0, 2 (the number the configuration writers use), 5 and 12, the longest, and the element lists that place the chip; the full sixteen are listed [below](#data-register-lengths). The board each chip sits on follows from the lists. **Inferred** from the symbol prefixes and the board each list describes: on the raster boards `tg` is the texture generator, `tm` the texture memory, `tf` the texture filter, `imp` the image processor and `pg` the pixel generator; on the display board `fm2` is the bridge chip, `xmap8` the XMAP, `voc1` the VOC video chip, `adv7160` a video DAC and `tmc22090` a video encoder; on the geometry board `hip` is the host interface, `bef` the back-end chip and `ged` the distributor. A suffix letter (`imp8d`, `tf1c`, `pg2b`, `tm1c`, `ged1b`, `hip1b`) marks a later revision of the same chip, which keeps its chip code except where the table shows a new one.

## Chain records

**Established** (every record below). A chain record is five words: the chip count, the total instruction-register bits of its chips (the script checks the sum), two words `jt_select_chip` fills at run time (the data-register bits of the current selection and the selected chip index, 0xffffffff in the image) and the pointer to the element list. The last columns give the first word in the image that holds the record's address, as a symbol and a word offset from it, and how many words hold it; the chain maps hold one pointer per scan-chain slot.

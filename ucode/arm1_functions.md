# ARM firmware (arm1.u) functions and data, one entry per symbol

The named functions and data of `usr/gfx/ucode/KONA/arm1.u` (IRIX 6.5.30m), one table row per debug-table symbol, grouped by what they do. [arm1_firmware.md](arm1_firmware.md) covers the structure (start-up, the input loop, the engine ports, the host-interface registers and the token handlers by group) and [arm1.md](arm1.md) the token map.

Each row was written from the code at its address in [arm1.s](arm1.s): its callers, the registers and state it touches and its effect. Labels as elsewhere: **established** (read from the code or the image), **inferred** (with the reasoning in the row). A code row cites `+0x` offsets from the read-only image base 0x0c000000, so `+0x2336c` is ARM address 0x0c02336c; data rows give the ARM address (initialised data from 0x04040260, zero-initialised data from 0x04067edc). "The state block" is the RAM the firmware addresses through r8 (base 0), which holds the GL state shadow; "the host-interface block" is the register window at 0x00200200 it addresses through r9. "Port n" is offset n in that window: 0x8c0 takes an engine handler address, 0x400 a descriptor, 0x474-0x47c operands, and reads at 0, 0x3c and 0x40 return payload words. Engine handler names are the `geif.u` slots of [ge.md](ge.md). Names that occur twice belong to two objects and have one row each.

## Start-up, exceptions and the run-time library

Reset, start-up, fault reporting, printing and the ARM C library helpers. A short lowercase name is written in backticks so it is read as code.

| Symbol | Address | What it is and does |
|---|---|---|
| `ucode` | 0x0c000000 | **Established** (`arm1.u` +0x0). The reset entry, the first instruction executed: it zeroes the state-block register, writes zero to 128 words spaced 0x20 bytes apart in the window at 0x00a00000, stores 0x28 at RAM address 0 and jumps through the word at 0x28, which holds the address of the start routine at +0x2c. Two other symbols with this name label runtime-library routines at +0x400e4 and +0x4015c, so a call listed as going to this name at +0x11784 really goes to +0x4015c. **Inferred:** the loop clears the instruction-cache tags, because that window is the tag area in the host-interface address map and 0x20 is the line stride. |
| `start` | 0x0c00002c | **Established** (`arm1.u` +0x2c). The firmware entry after the reset code: it sets the saved status to user mode, stores a return address at 0xffc and returns from exception through it, so the firmware proper runs in user mode. It then sets the state-block register to 0, the host-interface register to 0x00200200 and the stack to 0xffc, calls `init`, and loops forever: load the next handler address from the host-interface input port and jump to it. The code at +0x74-0x120 has no label of its own: it is the data-abort stub, which saves all registers and the live stack, sets the aborted flag at 0x04045e98 and rejoins this loop. |
| `vector_start` | 0x0c0002e8 | **Established** (`arm1.u` +0x2e8). The exception vector block of 16 words: eight pc-load instructions followed by the eight handler addresses they load. Reset, undefined instruction, prefetch abort, the reserved vector, interrupt and fast interrupt go to stubs that save the registers and print an error; the software-interrupt vector goes to the stack-restoring code at +0x128 and the data-abort vector to the stub at +0x74. `init_arm` copies the block to RAM address 0. |
| `vector_end` | 0x0c000328 | **Established** (`arm1.u` +0x328). The end of the vector block, at the same address as the first word of the static token list; the copy loop in `init_arm` stops here after 0x40 bytes, and no instruction loads this name. |
| `find_ucode` | 0x0c001ab0 | **Established** (`arm1.u` +0x1ab0). Searches the table of files the host loaded into ARM memory, up to ten records of 16 bytes starting 0x40 bytes past the free-memory base, for the first record at or after the starting index (first argument) whose tag word equals the second argument; it returns that index, or -1 when none matches. Its callers look up the engine microcode, the geometry-engine slot table and the distributor program by tag. |
| `init_arm` | 0x0c001aec | **Established** (`arm1.u` +0x1aec). Prepares the ARM's own memory: fills the stack area from just below its frame down to 0xd00 with the 0xdeadbeef pattern, copies the 16-word vector block to RAM address 0, points six pointer variables at the context save areas, stores a 0xdeaddead guard at 0xcfc, runs the line-mode table builder, and sets a work-around flag from a board-revision field in the configuration block. |
| `init_ge_board` | 0x0c003d0c | **Established** (`arm1.u` +0x3d0c). Start-up step for the geometry board: it runs in order the engine-presence, scan-chain, ARM-memory, host-interface, distributor and engine set-up routines and the back-end chip set-up, then tail-calls the routine that zeroes three board registers. `init` calls it once. |
| `init_simulator_hacks` | 0x0c003eb8 | **Established** (`arm1.u` +0x3eb8). Late start-up step that is only partly simulator-specific. It always sets read-back defaults (state-block words 0xc98-0xca0), writes screen-size values built from state-block bytes 0x40-0x45 to raster and image-processor registers unless the simulator's skip word at RAM 0x103c is set, and sets state-block bytes 0x86c-0x873 to fixed values. In the simulator it first fills bytes 0x40-0x45 with a 1280 by 1024 screen size and a third value of 1, and ends by sending the pipe-setup handler once per engine; when bit 0x100 of a host-supplied flag word is set it clears a 1280 by 1024 rectangle in 32 passes plus one 0xaaaaaaaa pass. |
| `init` | 0x0c004108 | **Established** (`arm1.u` +0x4108). The start-up sequence: it reads the simulator bit from register 0x200000 into the data block, prints the banner and release strings, records the end of zero-initialised data as the free-memory base, runs scan-chain discovery, the geometry-board set-up, the display-state builder (not in the simulator), the raster-board and display-board set-up, stores three 16-bit values from state-block offsets 0x40-0x45 into the configuration block, then runs memory set-up, the simulator tweaks and a final pipe check. |
| `arm_initpipe` | 0x0c0042bc | **Established** (`arm1.u` +0x42bc). One instruction, a branch to `init`. No token-map entry and no code reaches it. **Inferred:** a restart entry for a debugger, because it would rerun the whole start-up sequence from outside. |
| `sleep` | 0x0c00437c | **Established** (`arm1.u` +0x437c). Busy-waits for the number of ticks in the first argument, watching the free-running counter at 0x2000b0 and handling the counter wrap, then returns. The display-generator code uses it between register writes that need settling time. |
| `fault_cookie` | 0x040516ec | **Established** (`arm1.u` 6.5.30m). Zero in the image; `fault()` writes 0xdead into it before printing the exception, so a debugger reading memory can tell that the firmware stopped in its fault handler. |
| `REV_REL` | 0x04067ed4 | **Established** (`arm1.u` 6.5.30m). A pointer to the string "sherwood-root", the build tree name that `init()` prints in its start-up banner. |
| `REV_VER` | 0x04067ed8 | **Established** (`arm1.u` 6.5.30m). A pointer to the string "0607201829" that `init()` prints beside the tree name. **Inferred:** a build time stamp (date and time). |

## Host interface, token map and input loop

Building the token map, the input loop, refused-token paths, payload helpers and the vertex-array token chains. The token map and its entry format are in [arm1.md](arm1.md); the loop is in [arm1_firmware.md](arm1_firmware.md#the-input-loop).

| Symbol | Address | What it is and does |
|---|---|---|
| `hipctl` | 0x0c000328 | **Established** (`arm1.u` +0x328). The static list of 512 token-map entries followed by an all-ones terminator at +0xff0: a word with bit 0 set is a whole entry, an even word takes the next word shifted left by 4. `init_hip` walks it to build the hardware token map, and the matrix-mode code copies fifteen of its entries back into that map at run time. |
| `hipwc` | 0x0c000ff4 | **Established** (`arm1.u` +0xff4). Table of 512 words, one per token, giving how many payload words `arm_bgnend` must read and discard when that token arrives inside a begin/end pair; 89 entries are zero (including the two double-precision matrix tokens, which have a special case) and the largest count is 36. |
| `arm_badcmd` | 0x0c0017f4 | **Established** (`arm1.u` +0x17f4). | `arm_bgnend` | 0x0c0018e4 | **Established** (`arm1.u` +0x18e4). It then writes register 0x200068: 1 for a token of kind 0 or kind 1, 0 for the end token. | `arm_divert` | 0x0c001a34 | **Established** (`arm1.u` +0x1a34). It never returns. **Inferred:** the divert path is never used, because the firmware only ever writes 0 or 1 to the control register that enables it. |
| `init_hip` | 0x0c001c60 | **Established** (`arm1.u` +0x1c60). Builds the token map: with the ARM-access bit set in register 0x200050, it expands the static list into 512 words stored both in the RAM copy and at the hardware map at 0x00400000, fills unlisted tokens with the bad-command handler, installs the begin/end and divert handlers at registers 0x20006c and 0x200054, then copies 512 words of the geometry-engine slot file into the slot table and packs the first 128 as halfword pairs at state-block offset 0x48. |
| `init_hip_tbus` | 0x0c003760 | **Established** (`arm1.u` +0x3760). Writes zero to three board registers, 0x441, then 0x453, then 0x463, through the engine register-write path, the last as a tail call. It is the final step of `init_ge_board`. |
| `arm_pipe_sync` | 0x0c0042c0 | **Established** (`arm1.u` +0x42c0). Handler for token 0x1ea: reads one payload word and passes it to `check_pipe_sync` as that routine's verbosity argument. | `arm_gerollcall` | 0x0c0042e0 | **Established** (`arm1.u` +0x42e0). Handler for token 0x1e5: reads one payload word, prints that it is issuing a roll call to every engine, sends each engine that word as an operand with the number-printing handler, runs `check_pipe_sync` and finishes with the last-word payload read. **Inferred:** a diagnostic in which each engine reports the word, from the handler's name. |
| `SendDGRply` | 0x0c0064f8 | **Established** (`arm1.u` +0x64f8). Called by every get-style display request. |
| `vertex_table` | 0x0405102c | **Established** (`arm1.u` 6.5.30m). 60 words indexed by vertex-array type and size giving the vertex token for each array format, zero where none exists; `varray_build_command` reads it to build the vertex-array token-map chain. |
| `normal_table` | 0x0405111c | **Established** (`arm1.u` 6.5.30m). 60 words giving the normal token for each array format (for example 0x76), zero where none exists; read by `varray_build_command`. |

## Engine and distributor set-up

Loading the distributor program and tables, the geometry-engine microcode and the bef chip, and the per-engine set-up commands ([arm1_firmware.md](arm1_firmware.md#how-a-handler-reaches-the-engines), [ged.md](ged.md)).

| Symbol | Address | What it is and does |
|---|---|---|
| `init_ged_ucode` | 0x0c001e20 | **Established** (`arm1.u` +0x1e20). Loads the distributor: it finds the program file by tag 0x4591 and writes its 1024 words through descriptor 0x48200020, replacing every word that names an engine slot with that slot's handler address, then writes a 16-word table through descriptor 0x42200020 and a 512-word table through 0x42600020, after resetting each write pointer. |
| `init_ged_regs` | 0x0c0020ec | **Established** (`arm1.u` +0x20ec). Writes power-up values into the distributor through descriptor-and-data store pairs: zeros and a few fixed constants, ten zero words, sixteen 0xfefefefe words, a 128-word table whose first 32 entries are zero and the rest 0xabcdabcd, the transfer mask 0x1000ef0f, and last the handler address of the pixel-colour entry into descriptor 0x58c00020. `init_ged` calls it once the handler table is written. |
| `init_ged` | 0x0c0024e8 | **Established** (`arm1.u` +0x24e8). Sets up the distributor at start-up: writes a flag byte of the state block through descriptor 0x44000020 (1 when bit 0x20 of a host-supplied flag word is clear and at most four engines are present, else 0), zero through 0x44200020 and the engine occupancy mask five times through 0x44400020; writes engine handler addresses into 43 of the 64 handler-table indexes (indexes 0x13-0x15 are not among them); calls `init_ged_regs`; then alternates small numbers between two neighbouring descriptors starting at 0x40000020 and fills a table through 0x50600020, and tail-calls the program loader. It prints a warning that the pre-production distributor is no longer supported when a revision nibble in the configuration block is zero. |
| `check_pipe_sync` | 0x0c002f7c | **Established** (`arm1.u` +0x2f7c). Synchronises the ARM with the engines: it writes 1 to the mailbox-valid register at 0x20009c, reads the real-time counter at 0x2000b0, sends that value to board registers 0x430 then 0x434 through the engine register-write path, spins a bounded time until the valid register reads non-zero, then compares the mailbox word at 0x2000a0 with the value sent. It returns one of four codes, 0 for valid-and-correct up to 3 for invalid-and-incorrect, printing the outcome (the all-good case only when the first argument is zero); it returns 0 at once in the simulator or when a bookkeeping word in the data block is set. |
| `init_ge_config` | 0x0c003164 | **Established** (`arm1.u` +0x3164). Works out which geometry engines are present: it clears an 8-entry list in the configuration block, then forms a mask from the engine count (or, in the simulator, from fields at RAM 0x1030-0x1034), ANDs it with the occupancy mask the host loader left in memory, and stores the count, the mask and the list of engine numbers. A mask that comes out empty prints a message and keeps the unmasked value. |
| `ungray` | 0x0c0032d4 | **Established** (`arm1.u` +0x32d4). Returns entry n of the 16-word table at 0x04040284; the table is the inverse of the 4-bit Gray code, so the geometry-board position code is decoded to a plain number. Only `init_ge` calls this routine; a second routine of the same name at +0x1a3e4 serves the scan-chain code. |
| `init_ge` | 0x0c0032e4 | **Established** (`arm1.u` +0x32e4). Brings up the geometry engines: it sets the grant bit in register 0x200004 when any of engines 4-7 is present, writes the engine masks through descriptors 0x44000020-0x44400020, loads every engine-microcode file found by tag 0x4593 word by word through the 0x46600020 data descriptor after setting the 0x46a00020 address descriptor, writes board-dependent constants chosen from the decoded board position, runs `mgeb_GlobalInitialize` on all engines, sends each engine its own numbering command and checks the pipe once per engine. | `init_bef` | 0x0c00375c | **Established** (`arm1.u` +0x375c). One instruction, a branch to the routine that sets up the shadow of the back-end chip's registers; it is called once from `init_ge_board`. |
| `compute_gedxfermask` | 0x0c012a98 | **Established** (`arm1.u` +0x12a98). Forces on, in the two distributor transfer-mask words in the state block at offsets 0xc90 and 0xc94, the bits the diagnostic engine load needs: bits 0-3 plus 8-11 plus 13-15 of the first word, and bits 8-11 plus 13-23 plus 28 of the second, so that every vertex attribute is transferred. | `set_ged_xfer_mask` | 0x0c012ba8 | **Established** (`arm1.u` +0x12ba8). About forty routines call it after they recompute the mask in the state block. |
| `XferMask` | 0x0c013098 | **Established** (`arm1.u` +0x13098). It adds 0xf00 (0x1e00 when the colour-index width at 0x1ce is non-zero) unless lighting is on without colour material and the lighting pointers are set. | `XferMaskRpos` | 0x0c01315c | **Established** (`arm1.u` +0x1315c). | `tbus_regwrite` | 0x0c015298 | **Established** (`arm1.u` +0x15298). | `befsh_addrs` | 0x04067c0c | **Established** (`arm1.u` 6.5.30m). 89 register addresses of the bef chip (starting at 0x441) that `init_geBefAddrs` broadcasts to every engine as one command; `arm_slop` also reads it. |

## Enable and disable

`arm_enable` and `arm_disable` take the capability number from the token's last payload word, check six ranges and jump through one pointer table per range; a number outside every range, or one whose slot holds `set_invalid_enum`, raises the GL invalid-enum error. Every routine except the multipass and unimplemented pairs first stores 1 (enable) or 0 (disable) in its byte of the enable block at state-block offsets 0x758-0x796, then does its work, so the block is the firmware's copy of the enable state; `enable_pop` walks the block and calls the matching routine for each byte. GL names in the entries are the public enum names for the capability numbers.

### Pixel path

**Established.** Pixel transfers (`DRAWPIXELS`, `READPIXELS`, `COPYPIXELS`, texture loads and reads, colour tables, convolution filters, bitmaps and the polygon stipple) are built from five stages chosen by a path number. The table `path` (0x04049698) holds ten records of five routine pointers, in this order: set up the raster boards, compute how the data is split across the engines, set up the distributor, load the engine pipeline, and finish.

| Path | Raster set-up | Split | Distributor | Engine pipeline | Finish |
|---|---|---|---|---|---|
| 0 colour stream | `SetupRM` | `CompCommonColorStream` | `SetupGED_ColorStream` | `SetupGE_ColorStream` | `PixEndRGBStream` |
| 1 luminance stream | `SetupRM` | `CompCommonLumStream` | `SetupGED` | `SetupGE_LuminanceStream` | `PixEndRGBStream` |
| 2 colour, line at a time (convolution) | `SetupRM` | `CompCommonColorLine` | `SetupGED` | `SetupGE_ColorLine` | `PixEndRGBLine` |
| 3 luminance, line at a time | `SetupRM` | `CompCommonLumLine` | `SetupGED` | `SetupGE_LuminanceLine` | `PixEndRGBLine` |
| 4 colour short circuit | `SetupRM` | `CompCommonColorStream` | `SetupGED_ColorStream` | `SetupGE_ShortCircuit` | `PixEndRGBStream` |
| 5 luminance short circuit | `SetupRM` | `CompCommonLumStream` | `SetupGED_ColorStream` | `SetupGE_ShortCircuit` | `PixEndRGBStream` |
| 6 colour index | `SetupRM` | `CompCommonIndexStream` | `SetupGED` | `SetupGE_IndexStream` | `PixEndRGBStream` |
| 7 depth | `SetupRM` | `CompCommonLumStream` | `SetupGED` | `SetupGE_DepthStream` | `PixEndRGBStream` |

| 9 FFT | `SetupRM_FFT` | `CompCommon_FFT` | `SetupGED_FFT` | `SetupGE_FFT` | `PixEnd_FFT` |

The engine pipeline is a chain of engine modules (the `mmo_*` slots of [ge.md](ge.md)). Each `Add*` routine appends one module and its parameters, each `U_*` routine writes a module's parameters into engine control memory (`WriteCram`) or external memory (`WriteEram`), and the last module of a chain is an output module chosen from a record table (below). **Inferred:** "short circuit" paths skip the floating-point stages and move integer data straight to the output, since their modules (`mmo_short*`) convert packed integers only.

### Output-module records and conversion lists

**Established** (the record tables and the routines that read them). An output module is described by a 7-word (28-byte) record: the engine slot of the module, the slot of its no-clamp variant (`NC`), the ARM routine that writes its parameters (a `U_m*` routine), a pixel tag table and a texel tag table (`ptagBig` or `ptagSmall`, `ttagBig` or `ttagSmall`), a pointer to a conversion record (`cvmg_*`), and a flag that is 1 with the "Big" tag tables. A record whose slots are `mges_TBUS_1` and whose other words are zero marks a format with no output module. For example the second record of `RGBAoutputModuleTable` is {`mmo_Pixout_8_16`, `mmo_Pixout_8_16NC`, `U_mPixout_8_16`, `ptagBig`, `ttagBig`, `cvmg_8_16_RGBA8`, 1}.

A conversion record is a list of {word count, pointer to a word list}: `cvmg_8_16_RGBA8` = {16, `RGBA8_8_16`, 16, a second list}. The word lists are the control words the `U_m*` routine copies into the module's engine control memory. **Inferred:** they program the module's packer for one framebuffer or texel format; the format is in the list name (RGBA8, RGB10A2, LA16, RGBA4, RGB5A1, R5G6B5, LA8, 16- and 32-bit luminance and depth split into four passes `_1st` to `_4th`, the texture formats `TEX_L4` to `TEX_A16`, and `_F` for float sources), and the suffix names the module family (`_8_16` for `mmo_Pixout_8_16`, `_2_4`, `_32`, `_4_8`, `RGB_in_RGBA`).

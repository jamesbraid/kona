# `libGLcore`: function reference by source file

Sources: the N32 `libGLcore.so` of IRIX 6.5.30m for the Kona (InfiniteReality) pipe, built with debug information, so every function belongs to a source file named in the library's own debug data (the per-file assembly is in [libglcore/asm/](../libglcore/asm/)). The other builds (O32, 64-bit, the IP35 variants) carry the same function names. Roles are **inferred** from the file name, the function names inside it and, for the pipe-facing files, the command emission documented in [ge.md](ge.md), [hip.md](hip.md) and [opengl.md](opengl.md); the software renderer files are the generic OpenGL fallback and say nothing about the hardware beyond which calls reach the pipe.

**Inferred** from the names and the neighbouring documents (the exact table each context installs was not traced for every call). A GL call reaches the pipe through one of four function families, picked by the dispatch table the context installs. `gl*` are the entry points, which jump through the table. `__glkonim_*` are the Kona immediate-mode functions that build commands and write them to the pipe FIFO. `__gllc_*`, `__glce_*`, `__glle_*` and `__glsplc_*` are the generic display-list compile, compile-and-execute, list-execute and pre-processed-compile functions, and `__glkonlc_*`, `__glkonle_*` the Kona versions that record or replay a list in pipe-side list memory. `__glim_*` are the generic immediate-mode functions of the software renderer, used when a call is not accelerated. Each family has one function per GL call, which is why the lists below are long.

## The extension string

**Established** (all six shipped builds: `usr/gfx/arch/IP27KONA`, `IP27KONA32`, `IP27KONA64`, `IP35KONA`, `IP35KONA32`, `IP35KONA64`, `libGLcore.so`; 64-bit IP27 build at 0x193828). The driver carries one 950-byte extension string of 46 names, byte-identical in every build and so for every board set, and a 424-byte string of 22 names beside it. The long string: `GL_EXT_abgr`, `blend_color`, `blend_logic_op`, `blend_minmax`, `blend_subtract`, `convolution`, `copy_texture`, `histogram`, `packed_pixels`, `polygon_offset`, `subtexture`, `texture`, `texture3D`, `texture_object`, `vertex_array`; `GL_SGI_color_matrix`, `color_table`, `texture_color_table`; `GL_SGIS_detail_texture`, `fog_function`, `multisample`, `point_line_texgen`, `point_parameters`, `sharpen_texture`, `texture_edge_clamp`, `texture_filter4`, `texture_lod`, `texture_select`; `GL_SGIX_calligraphic_fragment`, `clipmap`, `fog_offset`, `instruments`, `interlace`, `ir_instrument1`, `flush_raster`, `list_priority`, `reference_plane`, `shadow`, `shadow_ambient`, `sprite`, `subdiv_patch`, `texture_add_env`, `texture_lod_bias`, `texture_scale_bias`, `depth_texture`. The shorter string is the first 15 `EXT` names, the three `SGI` names, `GL_SGIS_texture_filter4`, `GL_SGIX_texture_scale_bias` and `GL_SGIX_subdiv_patch`. No string has `multitexture` or `preclip`. Which of the two strings a client sees is **inferred** to be the client library's subset against the full server string.

# The IrisGL compatibility library (`libgl.so`, IGLOO build): function reference

Sources: `usr/gfx/arch/IGLOO/libgl.so` and `IGLOO32/libgl.so` (6.5.30m). The library implements the older IrisGL programming interface (`ortho`, `winopen`, `qread`, `lmdef` and about 1,700 more calls) on top of OpenGL: the name IGLOO is in its own symbols (`__igloo*`). It is generic: it knows nothing about the Kona pipe except through OpenGL, so nothing here constrains the hardware. The groups below are **inferred** from the names and from the four per-call code shapes read in the disassembly (stated in each row). The same function lists appear in both builds.

## Version-string routine read in full

- `gversionIoctl` (`usr/gfx/arch/IGLOO/libgl.so` 0xec74b14, 556 bytes):
  **Established.** Builds the IrisGL version string for one graphics board by asking the kernel what the board is.
  `a0` is the destination string buffer and `a1` the board index; the frame is 3440 bytes and the routine returns nothing.
  It zeroes a 40-byte buffer at sp+3384 (`bzero`), opens "/dev/opengl" (0xecd5514) with flags 2048 and keeps the descriptor at sp+3380; a negative descriptor goes to the exit.
  `ioctl` 101 (`GFX_GETNUM_BOARDS`) with a zero argument must return more than zero, and `ioctl` 102 (the get-board-information graphics-driver request) with a request at sp+3424 (the board index, the buffer address, the length 40) must not be negative, or it goes to the exit with the descriptor still to close.
  It calls `uname` into a buffer at sp+36 and later uses that buffer's third field (sp+550, the release string).
  It compares the returned name with the table words "IMPACT", "IMPACTPC" and "IMPACTSR" (words at 0xecdd504, 0xecdd508 and 0xecdd50c) in that order with `strcmp`.
  When it matches the first or second, or fails to differ from the third, it takes the table entry for "IMPACT" from `match_gfx` (0xec747d0), then calls `__iglooMalloc` (0xec5fb60) for the number of bytes in the last word of the 40-byte buffer (sp+3420) and reads the full board record into it with a second `ioctl` 102 request (the index, the block, that size).
  When the allocation fails or the read is negative it keeps the "IMPACT" entry.
  When the record's byte at +45 is zero it replaces the entry with `match_gfx` of the word at 0xecdd510 ("IMPACT/1/1/0").
  The block is never freed.
  When the name is none of the three it asks `match_gfx` with the returned name itself.
  `match_gfx` walks the table of 12-byte entries that starts at 0xecdd514 (a code word, a name prefix and a version prefix), comparing each name prefix with `strncmp` over its `strlen`, and returns the terminating all-zero entry when none matches (its version prefix is then a null pointer, passed on as it is).
  The table runs "IR", "KONA", "IMPACT/1/1/0", "IMPACT", "IMPACTPC" and "IMPACTSR" with version prefixes GL4DINF, GL4DINF, GL4DSLD, GL4DIMP, GL4DIMP and GL4DIMP.
  It continues "RE", "GR2", "GR3", "NG1" and "NEWPORT" with GL4DRE, GL4DXG, GL4DXG, GL4DNP and GL4DNP.
  It ends "CRIME", "CRM", "ODYSSEY" and "ODYSSEYSIM" with GL4DCRM, GL4DCRM, GL4DODY and GL4DODY.
  The result is passed to `makeGversionString` (0xec7486c) with the destination, the entry's version prefix (word +8) and the release string: it copies seven bytes of the prefix with `strncpy`, ends the string at byte 7, appends "-" (0xecd5510) with `strcat`, appends the first three characters of the release with `strncat` and ends the string at byte 11.
  The descriptor is closed with `close` only when it is not negative (a branch-likely at 0xec74d10), and every path ends in the same epilogue.

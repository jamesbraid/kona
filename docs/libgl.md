# The GLX client library (`libGL.so`): function reference

Sources: `usr/gfx/arch/IP27KONA/libGL.so` (6.5.30m N32; the other builds under `usr/gfx/arch/` have the same names). Roles are **inferred** from the names, the neighbouring documents and the ioctl numbers the functions send (found by reading the code: the numbers cited are constants loaded immediately before the ioctl call). `libGL` is the library an OpenGL program links: it opens the GLX connection to the X server, picks a visual, creates a context and then either renders directly (a "direct context": the process attaches to the graphics board through the kernel driver and `libGLcore`, [libglcore.md](libglcore.md), writes commands straight to the pipe) or encodes each call into the GLX wire protocol (the "indirect" path, handled by `glx.so` in the server, [x-server-glx.md](x-server-glx.md)).

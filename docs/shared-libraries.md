# Shared libraries and servers that carry the Kona pipe

Five files installed for every graphics family but exercised by the InfiniteReality pipe: the two builds of the IrisGL compatibility library, the font manager library, the generic X server and its GLX module (IRIX 6.5.30m). Each entry says what the file is for, how it reaches the pipe and where its key entry points are. **Established** means the dependency list, device strings and symbol table named were read over the whole file; **inferred** says what the reading rested on. Function lists are in [irisgl.md](irisgl.md), [libfm.md](libfm.md), [xserver.md](xserver.md) and [x-server-glx.md](x-server-glx.md).

- `usr/gfx/arch/IGLOO/libgl.so`: **established** for structure and imports, **inferred** for the roles.
  The O32 IrisGL compatibility library: 1747724 bytes, ELF32 MIPS-II `noreorder`, 3811 functions from `.dynsym` and the debugging tables, SONAME `libgl.so`.
  It needs `libGL.so`, `libGLU.so`, `libXmu.so`, `libXsgivc.so`, `libXi.so`, `libXext.so`, `libX11.so.1`, `libm.so` and libc, so IrisGL calls are carried out by calling the OpenGL library and the video-control extension, not by writing to a pipe directly.
  The strings `/dev/opengl`, `/dev/tty`, `/dev/null` and `/usr/gfx/setmon -n %s 1>/dev/null 2>&1` show that a monitor change (`setmonitor`, with its encoders `gl_d_setmonitor` and `gl_g_setmonitor`) runs the command-line `setmon`.
  Entry points sit at `ginit` 0xec64164 (116 bytes), `gbegin` 0xec620d0, `winopen` 0xec63534, `foreground` 0xec6323c, `getgdesc` 0xec63dd4, `swapbuffers` 0xec6d350 and `gexit` 0xec659b0; the bridge to OpenGL is `GetOpenGLStrings` at 0xec72604 (1408 bytes), `DrawBufferIrisToOpen` at 0xec35b48 (4148 bytes) and `match_gfx` at 0xec747d0 (156 bytes).
- `usr/gfx/arch/IGLOO32/libgl.so`: **established** for structure and imports, **inferred** for the roles.
  The N32 build of the same library: 1833076 bytes, MIPS-III with the N32 `abi2` flag, the same 3811 names and the same imports and device strings as the O32 file; its DWARF addresses are stale, so the inventory has only the dynamic-symbol addresses.
  Its code is laid out differently: `ginit` is at 0xec641cc (172 bytes), `gbegin` at 0xec61640 (172 bytes), `winopen` at 0xec6319c (200 bytes), `foreground` at 0xec62db4, `getgdesc` at 0xec63d1c, `swapbuffers` at 0xec6fef8 and `gexit` at 0xec66174, each 44 to 56 bytes larger than its O32 counterpart.
  The three IrisGL window-system calls `GLXlink`, `GLXunlink`, `GLXwinset` and `GLXgetconfig` (with `__GL` twins) are **inferred** from their names to join an IrisGL window to a GLX drawable, which would be how a program written for the older interface ends up on the pipe.
- `usr/lib32/libfm.so`: **established** for the imports and symbols, **inferred** for the roles.
  The N32 font manager library: 683872 bytes, 791 functions with DWARF addresses that agree with `.dynsym`, SONAME `libfm.so`, needing only `libgl.so`, `libm.so` and libc.
  It names no device and no graphics ioctl: it parses bitmap, object and PostScript font files (`fmreadbitmapfont`, `fmreadobjfont`, `fmreadPostScriptFont`, with the BDF readers `__fm_bdfGetLine` and `__fm_bdfHexByte`) and draws strings through the IrisGL library, so the pipe sees only the calls that library makes.
  Its public entry points are `fminit` at 0xee2cbe0 (88 bytes), `fmfindfont` at 0xee2c838 (108 bytes), `fmscalefont` at 0xee2cea4 (132 bytes), `fmsetfont` at 0xee2cf88 (96 bytes) and `fmprstr` at 0xee2cdd8 (108 bytes).
- `usr/gfx/arch/GENERIC/Xsgi`: **established** for the entry points and device strings, **inferred** for the module loading.
  The generic X server: 3120928 bytes, ELF32 N32 `cpic`, 2936 functions from `.dynsym`, needing only `libm.so` and libc; the Kona code is not in it but in the modules it loads from `/usr/lib/X11/dyDDX` by the pattern `%s/%s.so`.
  `main` is at 0x10218270 (5600 bytes), `InitOutput` at 0x10233520 (1880 bytes), `InitInput` at 0x1016b660 (592 bytes), `Dispatch` at 0x101a9fa0 (6956 bytes) and `OsInit` at 0x1024db30.
  `ddxMakeDynamicModulePath` (0x10080080, 124 bytes) builds the module path, `ddxSetLoadType` (0x100cc040) selects how a module is brought in, and `ddxFindAvailableBoards..CGC` (0x10082870, 972 bytes) sends the generic ioctls 101 and 102 according to the inventory's ioctl scan (board count and board record), so it is where the server first learns that a pipe exists.
  It names the device nodes `/dev/opengl`, `/dev/gfx`, `/dev/input`, `/dev/shmiq`, `/dev/qcntl%d` and `/dev/xconns`, and loads the speech and font renderers with `dlopen`.
- `usr/lib/X11/dyDDX/glx.so`: **established** for the imports and entry points, **inferred** for the roles.
  The GLX server module: 646360 bytes, N32, 981 functions, SONAME `glx.so`, needing `libGLcore.so` and `libm.so`, with the device strings `/dev/opengl` and `/dev/zero`.
  Because it links `libGLcore.so`, an indirect GLX request is executed inside the server by the same driver code a direct client runs; the module's job is the protocol around it.
  `__glXExtensionInit` is at 0xec60f0 (1076 bytes), `__glXScreenInit` at 0xede6d0 (264 bytes), `glxInitDispatch` at 0xf015c0 (328 bytes), `glxThreadInit` at 0xee3ff0 and `__glXDisp_InitNames` at 0xec8700.
  The request handlers include `glxCreateContext` (0xef5690), `glxMakeCurrent` (0xeee9f0), `glxSwapBuffers` (0xec8b20, 1112 bytes), `glxIsDirect` (0xf07490), `glxJoinSwapGroupSGIX` (0xeeddc0, 1176 bytes) and `glxBindSwapBarrierSGIX` (0xeb0830, 780 bytes), and the hyperpipe handlers such as `glxQueryHyperpipeNetworkSGIX` and `glxHyperpipeConfigSGIX` carry the multi-pipe extension.

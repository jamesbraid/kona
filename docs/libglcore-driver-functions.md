# libGLcore: the large routines of the Kona driver

Read from the IP27 Kona N32 build of the 6.5.30m `libGLcore.so` (`usr/gfx/arch/IP27KONA32/libGLcore.so`; `usr/gfx/arch/IP35KONA32/libGLcore.so` holds the same code for every routine here), through a Ghidra decompile with the global-pointer and jump-table scripts of [ghidra/scripts/](../ghidra/scripts/README.md) read against the annotated assembly in [libglcore/asm/KONA/](../libglcore/asm/KONA/). Addresses are virtual addresses in the library. Command tokens are those of [GE.h](../GE.h). The command FIFO is the page at process address 0x4000, the context pointer is the word at process address 0x1010, and the context offsets quoted below are offsets into that context. A routine labelled inferred was read in the parts that decide its behaviour (argument checks, state it writes, tokens it sends, loops); one labelled established was read in full.

## State and context routines

- `__glkonCopyContext` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95fb60, 6876 bytes, `kon_attrib.c`):
  **Inferred.** The Kona side of glCopyContext. It does nothing unless the source context passed in is the current one (the word at process address 0x1010). For each bit of the attribute mask in `a2` it refreshes the destination's shadow copy by querying the pipe through the immediate-mode getters `__glkonim_GetFloatv`, `__glkonim_GetIntegerv`, `__glkonim_GetBooleanv` and `__glkonim_IsEnabled`. The bits are the GL attribute-group bits. Bit 0x1 (current) reads the current colour, index, normal, texture coordinate and raster position queries 0xb00 to 0xb09, bit 0x200 (accumulation buffer) the clear value 0xb80, bit 0x4000 (colour buffer) the alpha-test, blend and logic-op queries from 0xbc1, bit 0x40 (lighting) the lighting model plus, from `__glkon_get_special` request 0x10b, a block of light words and one 0x74-byte record per light completed by five `__glkonim_GetLightfv` calls, bit 0x1000 (transform) the matrix mode 0xba0, the normalise enable and six clip-plane enables with the 32-byte plane records copied by `memmove` from request 0x1cb, bit 0x20 (pixel mode) the colour-table parameters through `__glkonim_GetColorTableParameterfvSGI`, and bit 0x40000 (texture) the texture-generation words from request 0x134 together with `__glkonim_GetTexGeniv`, `__glkonim_GetTexParameteriv` and `__glkonim_GetTexParameterfv` for the 1D and 2D targets 0xde0 and 0xde1. Each enable that a group owns is folded into the packed enable words at context words 0x1c0 to 0x1c3, one bit per capability. Finally it sets bit 0 of context word 0x1ed7 and ORs the copied mask into word 0x1ed8, which marks those groups as shadowed. It is the pull-from-pipe counterpart of `__glkonResolveContext`.
- `__glkonResolveContext` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd961640, 8616 bytes, `kon_attrib.c`):
  **Inferred.** Replays the shadow state of the current context into the pipe. It loads a dirty-group mask from context offset 0x7b60 and, for each attribute-group bit that is set, calls the ordinary GL entry points with the stored values. Bit 0x1 sends the current colour, index, texture coordinate, normal and edge flag (`glColor4fv`, `glIndexf`, `glTexCoord4fv`, `glNormal3fv`, `glEdgeFlag`), bit 0x100 the depth function, mask and clear value, bit 0x4 the line width and stipple, bit 0x2 the point size, bit 0x8000 the five hint targets 0xc50 to 0xc54 from offsets 0x768 to 0x778, and bit 0x40 the shade model, colour material, the front and back (0x404, 0x405) material records at offsets 0x590 to 0x624 and the lights. The 133 call sites each of `glEnable` and `glDisable` test one bit apiece of the packed enable words at offsets 0x700 to 0x714. Three groups skip the entry points and write command words to the FIFO: the lights (token 0x119, a word count of 12 per light, then the 12 words of each light record), the texture-coordinate generation block (token 0x1d6, with words from offsets 0x7c4 to 0x9b0) and the transform attribute block (token 0x1ca, with the table at offset 0x6d4 passed to `__glkon_datavn`). It finishes by storing 0 to offset 0x7b60, so a second call does nothing. The callers are `__glkonim_PopAttrib` and `MakeCurrentRead` (`kon_context.s`).
- `__glkonim_PushAttrib` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95d8b0, 3408 bytes, `kon_attrib.c`):
  **Inferred.** The Kona glPushAttrib. Inside a begin it raises error 0x502. If the attribute stack has no storage yet and `__glkon_mem_alloc` fails for a block of the stack depth (context word 0x3b0) times 2048 bytes, it raises error 0x505. Otherwise it sends token 0xc9 with the attribute mask to the pipe, calls `__glkona_wait_rdata`, and saves host state into a new stack record of 0xbd0 bytes that is allocated the first time its slot is used, with a parallel stack whose entries are 0x105c bytes. The mask is stored first and the packed enable words from context words 0x1c0 to 0x1c6 are copied in. Each group bit then copies its fields out of the shadow block at context word 0x1ed9: bit 0x1 (current) the colour, normal, texture-coordinate, index and edge-flag words, bit 0x2000 (enable) the enable word with the extra texture bits from word 0x1ee4, bit 0x10000 (evaluator) the twelve words at context offsets 0x78c to 0x7b8 plus the auto-normal bit, bit 0x80 (fog) thirteen fog words, bit 0x20000 (list) the list base from word 0x1ef, and bit 0x20 (pixel mode) the pixel-map words at 0x280, the read buffer 0xc02 and, through `__glkonim_GetColorTableParameterfvSGI`, the colour-table parameters for the targets 0x80d0, 0x80d1, 0x80d2 and 0x80bc.
- `__glkonim_PopAttrib` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95e600, 4080 bytes, `kon_attrib.c`):
  **Inferred.** The Kona glPopAttrib. Inside a begin it raises error 0x502. First it sends the light-pop token 0x119 with a word count of 12 per light followed by the 12 words of each saved light record, then token 0xc8 with a zero word. When the stack pointer (context word 0x31bc) is at or below the base (0x31b8) it stops there, so an empty stack is not an error. Otherwise it pops the record, restores the groups named in the saved mask and replays them: bit 0x1 calls `glColor4fv`, `glIndexf`, `glNormal3fv`, `glTexCoord4fv` and `glEdgeFlag` from the saved words, bit 0x2000 (enable) restores the packed enable words at context offsets 0x700 and 0x704 and re-applies the texture targets 0xde0, 0xde1 and 0x806f through `__glkon_EnableTexture` and `ValidateHistogramSink`, and the evaluator group (bit 0x10000) enables or disables the nine one-dimensional evaluator targets 0xd90 to 0xd98 and the two-dimensional ones from 0xdb0 one by one with `__glkonim_Enable` and `__glkonim_Disable`. It then calls `__glkonResolveContext` for the remaining groups, so the dirty-group mask it leaves is consumed there.
- `__glKonTexParameter` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd968390, 6156 bytes, `kon_texture_attrib.c`):
  **Inferred.** The Kona texture-parameter setter behind the four glTexParameter entry stubs of `kon_texture_attrib.s`. `a4` points at the value and `a5` is zero for integer values, which are converted to float first; `a2` indexes the bound texture object. The parameter name chooses the branch. Name 0x813c (base level) stores the level at texture offset 0x158, rebuilds the mipmap set with `FUN_0d9663c0` and re-pushes state with `FUN_0d96e820`. Names 0x8179 and 0x817a (the post-texture filter bias and scale of the SGIX extension) clamp four values to the range 0 to 1, store them at texture offsets 0x1e0 and 0x1d0, set a bit per component in the word at offset 0x1f0 when the pair differs from the identity, pack each as a byte computed as x times 255 plus 0.5 into the words at offsets 0x1f4 and 0x1f8, and send token 0x1d7 with the texture dimension, the presence word and both packed words. Names 0x818e, 0x818f and 0x8190 (the level-of-detail bias per axis) store a float at offsets 0x214, 0x218 and 0x21c and overwrite one byte of the parameter word at offset 0x4c. Name 0x8173 (clipmap offset) stores two non-negative integers at offsets 0x1a4 and 0x1a8 and packs them into the word at offset 0x58. Names 0x819a to 0x819d (the SGIX shadow compare switch, operator and the two compare values) store 0 or 1 at offset 0x1fc and 0x819c or 0x819d at offset 0x200. The routine calls the per-texture update hook at offset 0x100 when the texture is the one bound on the active unit.

## Subdivision patches

- `__glkonim_SubdivPatchSGIX` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd989060, 15692 bytes, `kon_subdiv.c`):
  **Inferred.** The Kona glSubdivPatchSGIX: it turns a bicubic-style patch given as four arrays of control values into one subdivision-patch command stream. `a0` points at four array pointers, each array starting with an element count and then the values; a null `a0` raises error 0x501 and counts above 8, 9, 9 and 8 for the four arrays also raise 0x501. `a1` and `a2` point at four optional byte-array pointers each (the bytes packed into the patch command); a null pointer is replaced by a zeroed 32-byte local buffer. The vertex format is context word 0xa0fc, set by `__glkonim_SubdivPatchParameterfSGIX`: it selects 3, 4, 5 or 6 floats per vertex (stored at context word 0xa100) for the values 0x2a21, 0x2a23, 0x2a27 and 0x2a29, and the packed-vertex token 0x1ab, 0x1ac, 0x1af or 0x1b0 for the 24 vertices it sends. The routine first sends token 0x1d1 (patch setup) with that format value. It then gathers the four edge strips of the patch into a local array of 24 vertex slots, calling the local `CopyVertex` to duplicate a boundary vertex when an adjacent array is absent, and clears edge-presence bits in two masks (initially 0x00ffffff and 0x1fffffff) for each edge whose neighbour does not match; the masks and the flag word are stored at context offsets 0xa118, 0xa11c and 0xa114. It sends token 0x1d0 with the flag word and both masks, followed (when the flag word is non-negative) by the packed edge bytes of `a1` and `a2`, then token 0x1d4 with a zero word, then twelve passes of two vertices each as the chosen packed-vertex token with 3 to 6 floats, calls `glEnd`, and ends with token 0x1d2 and a zero word.

## Pixel and image routines

- `__glkonim_GetHistogramEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd984c00, 7604 bytes, `kon_histogram.c`):
  **Inferred.** The Kona glGetHistogramEXT. It raises error 0x502 inside a begin, and error 0x500 for a target other than 0x8024, a format outside 0x1903 to 0x190a and 0x8000, or a type outside 0x1400 to 0x1406 and 0x8032 to 0x8036; the packed types need format 0x1908 or it raises 0x502. A histogram width of 0 at context offset 0x4e0 returns at once. Otherwise it fetches the counters from the pipe: through `__glkon_get_special` request 0x104 when the product of context word 0x7b50, the width and the format's component count is below 4093 words, and for a larger table by filling a request record (request 0x104, four bytes per entry) and calling `__glKon_ioctl` with request 10000 between `__glkon_SuspendSelectfeed` and `__glkon_ResumeSelectfeed`, reporting a failure through `strerror`. A non-zero reset argument then sends token 0x103 with 0x8024, so the pipe clears the histogram after the read. The counters are unpacked into the caller's buffer using the pixel-pack state reached through context offset 0x8c6c (the fields at +0x4 to +0x18), the component selection of the `__glkon_formats` table (0x28 bytes per format) and the element size from `__glSpecBytesPerElement`: the buffer is cleared with `bzero`, then a per-type loop adds each counter into its element, with separate loops for 32-bit integers, 16-bit integers and bytes.

- `__glkonim_CopyPixels` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd951f10, 2796 bytes, `kon_pixel.c`):
  **Established.** The Kona glCopyPixels. A begin raises 0x502 and the argument check `ParseErrorCopy` (0xd950130) can end the call. Any other copy made with the read-buffer level word at +3460 equal to -3 and a 0x30000000 mode set goes to `__glkon_OverlappedCopy`. When the two pixel-zoom floats at context +744 and +748 are not both 1.0 the routine writes `HP_COPYISOVERLAPPED` (token 272) with x, y, width and height, waits for read data and, if bit 2 of the reply is set, calls `__glkon_OverlappedCopy`. The width limit comes from the pair at context words 0x22e4 and 0x22e5 (or 0x22f4 and 0x22f5 when the two format words at +3256 and +3260 are equal, indexed by the filter index times two) when a convolution target 0x81c5 is active, and from words 0x22f4 and 0x22f5 when a 0x30000000 mode is set; with no limit, or a width within it, the copy is one token 0x38 of seven words (x, y, width, height, a zero destination offset, the type and the flag word 0).   **Established.** The Kona glGetMinmaxEXT, read from the whole decompile against the assembly of `kon_histogram.s`. ## Vertex array drawing

- `__glkonim_DrawArraysEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95af60, 2196 bytes, `kon_vertarray.c`):
  **Established.** The Kona glDrawArraysEXT, taking the mode in `a0`, the first index in `a1` and the count in `a2`. Inside a begin it raises error 0x502, a negative first or count raises 0x501 and a mode of 10 or more raises 0x500. A zero count, or an array combination (word at context +5416) whose bits are set in the mask at +35532, draws nothing. The packed form is tried first when the colour buffer exists and the mode word at +1792 has none of the bits 0x3c0000 set (or has bits 0xc0000, 0x100000 and 0x200000 all set): the array-state words at +5400 and +5404 are ANDed, the result must have bits 28 to 31 clear, a non-zero low byte and bit 27 clear, and its four nibble pairs are looked up in the tables at data offsets 0x54dc, 0x53ec, 0x54fc and 0x55dc into a four-bit code that must give a negative entry in the table at 0x56d0 with no unused pair; when the first table entry is not zero the stride at +5124 must also be a non-zero multiple of 4 and bit 0x400000 of +1792 clear. If the tests pass it calls `__glKonSendPackedVertex` with the mode, first, count and that format (with bit 0x100000 added when bit 0x40 of +1792 is set and the first table entry is 0) and returns without drawing again. Otherwise it takes the per-combination sender from the table at +12716 indexed by the combination, which is skipped when it is the no-op, refreshes the compound-command word with `update_cmpnd_cmd` when the dirty mask at +35528 has the combination bit, and draws. A count below 0x9ffff is one `glBegin` of the mode, `HP_VARRAY_SETUP` (token 385) with a zero word, the sender called with the count less its remainder against the integer part of 32 divided by the combination's element count (from `__glkon_varray_elem_count`), `HP_VARRAY_UNSETUP` (token 419) with a zero word and `glEnd`. A larger count is cut into chunks of 0x9ffff less a per-mode byte from a table (0 for most modes, 1 for lines and strips, 3 for quads), each advancing the first index by the chunk less a per-mode overlap byte (1 for line strips and fans, 2 for triangle and quad strips), so shared vertices carry across chunks. The generic loop does one `glBegin` around all chunks. Line loops begin a line strip (mode 3) per chunk and re-send the array elements at index 0 at the end of the last chunk to close the loop; fans and polygons (modes 6 and 9) begin a fan per chunk and send the elements at index 0 first as the hub.
## Evaluator mesh drawing

- `__glKonEvalMesh2DHost` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd97ceb0, 2188 bytes, `kon_eval.c`):
  **Established.** The host-side tessellation of glEvalMesh2D for the point (0x1b00), line (0x1b01) and fill (0x1b02) modes, called with the mode in `a0` and the column range and row range in `a1` to `a4`. It returns at once if the word at context offset 0x7a8 or the row count at 0x7b8 is 0 or a range is empty; any other mode returns too. The second grid parameter of row `n` is `n` times the step at 0x7b4 plus the origin at 0x7ac, taken exactly as the end value at 0x7b0 on the last row (word 0x7b8 is the last row number). Columns are done in blocks of at most 256 points, advancing the first column by 0x100 for points and by 0xff for lines and fill so that adjacent blocks share one column; a final block takes the remainder. Drawing uses the begin and end entries at offsets 0x1c and 0x2c of the table at context offset 0x17f4 and the local evaluators `EvalRow2D` (0xd97c490) and `Eval2Rows` (0xd97c850), with two 16 KB stack buffers that swap roles each row. Points: for every row of the block, begin 0 (points), `EvalRow2D` with its emit flag on, end. Lines: the first row of the block is a line strip (begin 3); each later row is evaluated as a line strip and then, with begin 1 (lines), `Eval2Rows` joins the previous row's buffer to this one's for the block's column count (0xff full blocks, the remainder in the last), then end. Fill: the first row is evaluated into a buffer with no emission, and every later row is evaluated the same way and drawn against the previous one as a quad strip (begin 8) by `Eval2Rows` for 0x100 columns in full blocks and the remainder in the last, then end.
## Evaluator support

- `changebasis` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd979e70, 6860 bytes, `kon_eval.c`):
  **Inferred.** Rewrites one polynomial curve from its Bezier control values into a second set of coefficients. The arguments are the input values, the order (control point count), the output and the element stride; the same three-word stride applies to every component. The first output is always the first control value. The order, below 16, indexes a jump table of unrolled cases (the 6.5.30m decompiler of the repository could not recover it, so it was read through Ghidra with the jump-table script). The jump-table entries (at the constant page plus 0x480) send orders 0 and 1 to a bare return after that copy and order 2 to a case that copies the second value across. Order 3 produces the first value, the last value and 2 times the middle value minus the first and last. Order 4 produces the first value, the last value, 3 times the second minus 2 times the first and minus the last, and the first minus 3 times the second plus 3 times the third minus the last. Orders 5 to 15 follow the same form, order 15 producing fourteen further values and order 12 eleven, with integer weights that grow with the order (14, 12, 11, 9, 3, 2 and 88 appear among the double constants). The outputs are written first to a local array and then stored at the output stride.

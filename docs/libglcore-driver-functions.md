# libGLcore: the large routines of the Kona driver

Read from the IP27 Kona N32 build of the 6.5.30m `libGLcore.so` (`usr/gfx/arch/IP27KONA32/libGLcore.so`; `usr/gfx/arch/IP35KONA32/libGLcore.so` holds the same code for every routine here), through a Ghidra decompile with the global-pointer and jump-table scripts of [ghidra/scripts/](../ghidra/scripts/README.md) read against the annotated assembly in [libglcore/asm/KONA/](../libglcore/asm/KONA/). Addresses are virtual addresses in the library. Command tokens are those of [GE.h](../GE.h). The command FIFO is the page at process address 0x4000, the context pointer is the word at process address 0x1010, and the context offsets quoted below are offsets into that context. A routine labelled inferred was read in the parts that decide its behaviour (argument checks, state it writes, tokens it sends, loops); one labelled established was read in full.

## State and context routines

- `__glkonCopyContext` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95fb60, 6876 bytes, `kon_attrib.c`):
  **Inferred.** The Kona side of glCopyContext. It does nothing unless the source context passed in is the current one (the word at process address 0x1010). For each bit of the attribute mask in `a2` it refreshes the destination's shadow copy by querying the pipe through the immediate-mode getters `__glkonim_GetFloatv`, `__glkonim_GetIntegerv`, `__glkonim_GetBooleanv` and `__glkonim_IsEnabled`. The bits are the GL attribute-group bits. Bit 0x1 (current) reads the current colour, index, normal, texture coordinate and raster position queries 0xb00 to 0xb09, bit 0x200 (accumulation buffer) the clear value 0xb80, bit 0x4000 (colour buffer) the alpha-test, blend and logic-op queries from 0xbc1, bit 0x40 (lighting) the lighting model plus, from `__glkon_get_special` request 0x10b, a block of light words and one 0x74-byte record per light completed by five `__glkonim_GetLightfv` calls, bit 0x1000 (transform) the matrix mode 0xba0, the normalise enable and six clip-plane enables with the 32-byte plane records copied by `memmove` from request 0x1cb, bit 0x20 (pixel mode) the colour-table parameters through `__glkonim_GetColorTableParameterfvSGI`, and bit 0x40000 (texture) the texture-generation words from request 0x134 together with `__glkonim_GetTexGeniv`, `__glkonim_GetTexParameteriv` and `__glkonim_GetTexParameterfv` for the 1D and 2D targets 0xde0 and 0xde1. Each enable that a group owns is folded into the packed enable words at context words 0x1c0 to 0x1c3, one bit per capability. Finally it sets bit 0 of context word 0x1ed7 and ORs the copied mask into word 0x1ed8, which marks those groups as shadowed. It is the pull-from-pipe counterpart of `__glkonResolveContext`.
- `__glkonResolveContext` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd961640, 8616 bytes, `kon_attrib.c`):
  **Inferred.** Replays the shadow state of the current context into the pipe. It loads a dirty-group mask from context offset 0x7b60 and, for each attribute-group bit that is set, calls the ordinary GL entry points with the stored values. Bit 0x1 sends the current colour, index, texture coordinate, normal and edge flag (`glColor4fv`, `glIndexf`, `glTexCoord4fv`, `glNormal3fv`, `glEdgeFlag`), bit 0x100 the depth function, mask and clear value, bit 0x4 the line width and stipple, bit 0x2 the point size, bit 0x8000 the five hint targets 0xc50 to 0xc54 from offsets 0x768 to 0x778, and bit 0x40 the shade model, colour material, the front and back (0x404, 0x405) material records at offsets 0x590 to 0x624 and the lights. The 133 call sites each of `glEnable` and `glDisable` test one bit apiece of the packed enable words at offsets 0x700 to 0x714. Three groups skip the entry points and write command words to the FIFO: the lights (token 0x119, a word count of 12 per light, then the 12 words of each light record), the texture-coordinate generation block (token 0x1d6, with words from offsets 0x7c4 to 0x9b0) and the transform attribute block (token 0x1ca, with the table at offset 0x6d4 passed to `__glkon_datavn`). It finishes by storing 0 to offset 0x7b60, so a second call does nothing. The callers are `__glkonim_PopAttrib` and `MakeCurrentRead` (`kon_context.s`).
- `__glkonim_PushAttrib` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95d8b0, 3408 bytes, `kon_attrib.c`):
  **Inferred.** The Kona glPushAttrib. Inside a begin it raises error 0x502. If the attribute stack has no storage yet and `__glkon_mem_alloc` fails for a block of the stack depth (context word 0x3b0) times 2048 bytes, it raises error 0x505. Otherwise it sends token 0xc9 with the attribute mask to the pipe, calls `__glkona_wait_rdata`, and saves host state into a new stack record of 0xbd0 bytes that is allocated the first time its slot is used, with a parallel stack whose entries are 0x105c bytes. The mask is stored first and the packed enable words from context words 0x1c0 to 0x1c6 are copied in. Each group bit then copies its fields out of the shadow block at context word 0x1ed9: bit 0x1 (current) the colour, normal, texture-coordinate, index and edge-flag words, bit 0x2000 (enable) the enable word with the extra texture bits from word 0x1ee4, bit 0x10000 (evaluator) the twelve words at context offsets 0x78c to 0x7b8 plus the auto-normal bit, bit 0x80 (fog) thirteen fog words, bit 0x20000 (list) the list base from word 0x1ef, and bit 0x20 (pixel mode) the pixel-map words at 0x280, the read buffer 0xc02 and, through `__glkonim_GetColorTableParameterfvSGI`, the colour-table parameters for the targets 0x80d0, 0x80d1, 0x80d2 and 0x80bc.
- `__glkonim_PopAttrib` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95e600, 4080 bytes, `kon_attrib.c`):
  **Inferred.** The Kona glPopAttrib. Inside a begin it raises error 0x502. First it sends the light-pop token 0x119 with a word count of 12 per light followed by the 12 words of each saved light record, then token 0xc8 with a zero word. When the stack pointer (context word 0x31bc) is at or below the base (0x31b8) it stops there, so an empty stack is not an error. Otherwise it pops the record, restores the groups named in the saved mask and replays them: bit 0x1 calls `glColor4fv`, `glIndexf`, `glNormal3fv`, `glTexCoord4fv` and `glEdgeFlag` from the saved words, bit 0x2000 (enable) restores the packed enable words at context offsets 0x700 and 0x704 and re-applies the texture targets 0xde0, 0xde1 and 0x806f through `__glkon_EnableTexture` and `ValidateHistogramSink`, and the evaluator group (bit 0x10000) enables or disables the nine one-dimensional evaluator targets 0xd90 to 0xd98 and the two-dimensional ones from 0xdb0 one by one with `__glkonim_Enable` and `__glkonim_Disable`. It then calls `__glkonResolveContext` for the remaining groups, so the dirty-group mask it leaves is consumed there.
- `__glKonTexParameter` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd968390, 6152 bytes, `kon_texture_attrib.c`):
  **Inferred.** The Kona texture-parameter setter behind the four glTexParameter entry stubs of `kon_texture_attrib.s`. `a4` points at the value and `a5` is zero for integer values, which are converted to float first; `a2` indexes the bound texture object. The parameter name chooses the branch. Name 0x813c (base level) stores the level at texture offset 0x158, rebuilds the mipmap set with `FUN_0d9663c0` and re-pushes state with `FUN_0d96e820`. Names 0x8179 and 0x817a (the post-texture filter bias and scale of the SGIX extension) clamp four values to the range 0 to 1, store them at texture offsets 0x1e0 and 0x1d0, set a bit per component in the word at offset 0x1f0 when the pair differs from the identity, pack each as a byte computed as x times 255 plus 0.5 into the words at offsets 0x1f4 and 0x1f8, and send token 0x1d7 with the texture dimension, the presence word and both packed words. Names 0x818e, 0x818f and 0x8190 (the level-of-detail bias per axis) store a float at offsets 0x214, 0x218 and 0x21c and overwrite one byte of the parameter word at offset 0x4c. Name 0x8173 (clipmap offset) stores two non-negative integers at offsets 0x1a4 and 0x1a8 and packs them into the word at offset 0x58. Names 0x819a to 0x819d (the SGIX shadow compare switch, operator and the two compare values) store 0 or 1 at offset 0x1fc and 0x819c or 0x819d at offset 0x200. The routine calls the per-texture update hook at offset 0x100 when the texture is the one bound on the active unit.

## Subdivision patches

- `__glkonim_SubdivPatchSGIX` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd989060, 15692 bytes, `kon_subdiv.c`):
  **Inferred.** The Kona glSubdivPatchSGIX: it turns a bicubic-style patch given as four arrays of control values into one subdivision-patch command stream. `a0` points at four array pointers, each array starting with an element count and then the values; a null `a0` raises error 0x501 and counts above 8, 9, 9 and 8 for the four arrays also raise 0x501. `a1` and `a2` point at four optional byte-array pointers each (the bytes packed into the patch command); a null pointer is replaced by a zeroed 32-byte local buffer. The vertex format is context word 0xa0fc, set by `__glkonim_SubdivPatchParameterfSGIX`: it selects 3, 4, 5 or 6 floats per vertex (stored at context word 0xa100) for the values 0x2a21, 0x2a23, 0x2a27 and 0x2a29, and the packed-vertex token 0x1ab, 0x1ac, 0x1af or 0x1b0 for the 24 vertices it sends. The routine first sends token 0x1d1 (patch setup) with that format value. It then gathers the four edge strips of the patch into a local array of 24 vertex slots, calling the local `CopyVertex` to duplicate a boundary vertex when an adjacent array is absent, and clears edge-presence bits in two masks (initially 0x00ffffff and 0x1fffffff) for each edge whose neighbour does not match; the masks and the flag word are stored at context offsets 0xa118, 0xa11c and 0xa114. It sends token 0x1d0 with the flag word and both masks, followed (when the flag word is non-negative) by the packed edge bytes of `a1` and `a2`, then token 0x1d4 with a zero word, then twelve passes of two vertices each as the chosen packed-vertex token with 3 to 6 floats, calls `glEnd`, and ends with token 0x1d2 and a zero word.

## Pixel and image routines

- `__glkonim_GetHistogramEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd984c00, 7604 bytes, `kon_histogram.c`):
  **Inferred.** The Kona glGetHistogramEXT. It raises error 0x502 inside a begin, and error 0x500 for a target other than 0x8024, a format outside 0x1903 to 0x190a and 0x8000, or a type outside 0x1400 to 0x1406 and 0x8032 to 0x8036; the packed types need format 0x1908 or it raises 0x502. A histogram width of 0 at context offset 0x4e0 returns at once. Otherwise it fetches the counters from the pipe: through `__glkon_get_special` request 0x104 when the product of context word 0x7b50, the width and the format's component count is below 4093 words, and for a larger table by filling a request record (request 0x104, four bytes per entry) and calling `__glKon_ioctl` with request 10000 between `__glkon_SuspendSelectfeed` and `__glkon_ResumeSelectfeed`, reporting a failure through `strerror`. A non-zero reset argument then sends token 0x103 with 0x8024, so the pipe clears the histogram after the read. The counters are unpacked into the caller's buffer using the pixel-pack state reached through context offset 0x8c6c (the fields at +0x4 to +0x18), the component selection of the `__glkon_formats` table (0x28 bytes per format) and the element size from `__glSpecBytesPerElement`: the buffer is cleared with `bzero`, then a per-type loop adds each counter into its element, with separate loops for 32-bit integers, 16-bit integers and bytes.

- `__glkonim_CopyPixels` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd951f10, 2796 bytes, `kon_pixel.c`):
  **Inferred.** The Kona glCopyPixels. It raises error 0x502 inside a begin. A colour copy (type 0x1800) made while bit 0x100 of the word at context offset 0x704 is set and the word at offset 0x564 holds 0x81c6 must have a width equal to a table entry (constant-page offset 0x28b0, found by counting how many halvings of the width fit), and raises error 0x501 otherwise; with that match it sends token 0x38 (`HP_COPYPIXELS`) with seven words after the token: x, y, width, height, a zero destination offset, the type and a zero flag word. The general colour path sends the same token once per strip with a destination x offset that advances by the strip width, splitting a copy wider than the pipe limit (taken from the table at context words 0x22e4 to 0x22f5) into equal strips plus a final partial one, in forward order or, when bit 0 of the flag word from the local `FUN_0d952a50` is set, from the last strip back, so that overlapping rows are read before they are overwritten. Overlapping cases that this cannot express are handed to `__glkon_OverlappedCopy`. When a convolution filter is active the routine takes the slow path instead: it allocates a scratch buffer through the context allocator, reads the source back with `__glkonim_ReadPixels` as RGBA unsigned shorts (0x1908, 0x1403) in column strips, brackets the reads with `__glKonSetNoModeState` values 0x60000000, 0x20000000 and 0, parses each strip with `__glKonParseHostImage`, re-sends it through the local `FUN_0d951aa0`, and frees the buffer with the allocator's release hook.
- `__glkonim_GetMinmaxEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd986d00, 1876 bytes, `kon_histogram.c`):
  **Inferred.** The Kona glGetMinmaxEXT, read from the assembly of `kon_histogram.s` (source lines 495 to 629) and the decompile. It raises error 0x502 inside a begin, 0x500 for a target other than 0x802e, a format outside 0x1903 to 0x190a and 0x8000 or a type outside 0x1400 to 0x1406 and 0x8032 to 0x8036, and 0x502 for the packed types with the wrong format (0x1907 for 0x8032, 0x1908 for 0x8033 to 0x8036). It makes no FIFO store, and the assembly never reads the reset argument in `a1`, so a glGetMinmaxEXT with reset set does not send the reset-minmax token (0x108) from this routine. The two result entries (minimum and maximum) come from `__glkon_get_special` request 0x109, whose word before the returned pointer holds the internal format. Each requested component is picked with the `__glkon_formats` component mask, converted to the caller's type through a seven-entry jump table on the type (0x1400 to 0x1406), calling `floorf` in the float-to-integer cases, and stored with the pixel-pack alignment, row and skip fields reached through context offset 0x8c6c.
- `__glkonim_ColorTableSGI` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd981420, 2192 bytes, `kon_colortable.c`):
  **Inferred.** The Kona glColorTableSGI. It raises error 0x502 inside a begin, 0x500 for a format outside 0x1903 to 0x190a and 0x8000, a type outside the 0x1400 to 0x1406 and 0x8032 to 0x8036 ranges, or an internal format outside 0x1906 to 0x190a and 0x803b to 0x805b, 0x502 for a packed type with the wrong format, and 0x501 for a negative or non-power-of-two width. The target selects a branch through a 26-entry jump table from 0x80bc: four targets use host-side table slots at context offsets 0x1588, 0x1628, 0x16c8 and 0x1768 with width caps of 0x10000, 0x10000, 0x10000 and 0x1000 (and tighter caps by internal format at the 0x400 and 0x800 boundaries), and three use the pipe-side tables at context offsets 0x8b30, 0x8b48 and 0x8b60 with the table kind 4, 5 and 6, where a width above 0x10000 raises error 0x8031. When the local `FUN_0d981360` accepts the new size it brackets the load with token 0x111 (`HP_PIXEL_NOMODE`): first with the words 8 and 0x40000000, then token 0xe8 (`HP_COLORTABLE`) with nine words (target, internal format, width, the width plus -1.0 as a float, format, type, offset, a data-by-DMA flag masked to 2 bits and a row mode), the table pixels through `__glKonSendData`, and finally token 0x111 with 8 and 0. When it refuses, the same token 0xe8 goes out with the width fields zeroed and no pixels.

- `__glKonCopyTexImage` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd955350, 2588 bytes, `kon_pixel.c`):
  **Inferred.** Sends the pipe's copy-framebuffer-to-texture command for one glCopyTexImage request, passed in `a0` as a record whose first word is the width. It does nothing unless the byte at context offset 0xc94 is non-zero, and it sets bit 0x8000 of record word 0x21 when the pixel-mode flag (bit 0x20 of the word at offset 0x704) is on. When bit 0x100 of that word is set, offset 0x564 holds 0x81c5 and the target in record word 8 is 0, 0xde1 or 0xde0 with its enable bit set in the word at offset 0x700, it takes a filter-aware path that sizes the strips from the convolution filter (`GetConvolutionFilter`, size at filter offset 0x40). Otherwise it limits the width to what the pipe can read in one pass: a limit read from context word 0x8b94 or 0x8bd4 (the pair at 0x8b90 and 0x8bd0 on the filter path), rounded down to a multiple of 8, with the query `GetSingleCompFromPipe` (0x42, or 0x82 on the filter path) allowed to raise it. A width inside the limit, a multiple of 8 or a power of two goes out as one token 0xfd (`HP_COPYTEXIMAGE`) of 17 words from the record: source x and y, width, height, first column, and the texel-load words from record words 0x19 to 0x23. A wider copy goes out as a run of 0xfd tokens of the limit's width, each advancing the source x (record word 9) and the destination column (word 0x1b) by that width, and the remainder is sent as one token per set bit of a four-entry mask table at constant-page offset 0x2ae0, so each piece is a power of two. Bit 2 of record word 0x21 is set on every path that takes the strip loop.

## Vertex array drawing

- `__glkonim_DrawArraysEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95af60, 2196 bytes, `kon_vertarray.c`):
  **Inferred.** The Kona glDrawArraysEXT, taking the mode in `a0`, the first index in `a1` and the count in `a2`. Inside a begin it raises error 0x502, a negative first or count raises 0x501, and a mode of 10 or more is ignored. A zero count or an array combination whose enable bits at context offset 0x8acc are set draws nothing. When the combination can be packed (the array-state words at context offsets 0x1518 and 0x151c, decoded through the tables at constant-page offsets 0x53ec, 0x54dc, 0x54fc and 0x55dc into a format word whose sign bit says the pipe has a packed form, with the stride word at offset 0x1404 required to be a multiple of four) it calls `__glKonSendPackedVertex` with the mode, first, count and format and then continues into the path below. In every case it picks the per-combination sender from the table at context offset 0x31ac, indexed by the combination number at offset 0x1528, runs `glBegin`, sends token 0x181 (`HP_VARRAY_SETUP`) with a zero word, calls the sender for a batch of vertices rounded down to a multiple of 32 divided by the array's element count (from `__glkon_varray_elem_count`), sends token 0x1a3 (`HP_VARRAY_UNSETUP`) with a zero word and calls `glEnd`. A count of 0x9ffff or more is split into chunks of at most 0x9ffff minus a per-mode overlap, one begin-sender-unsetup cycle per chunk, so primitives that share vertices across a chunk keep their continuity.

## Evaluator mesh drawing

- `__glKonEvalMesh2DHost` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd97ceb0, 2188 bytes, `kon_eval.c`):
  **Inferred.** The host-side tessellation of glEvalMesh2D for the point (0x1b00) and line (0x1b01) modes, called with the mode in `a0` and the column range and row range in `a1` to `a4`. The grid description is in the context: the origin, end and step floats at offsets 0x7ac, 0x7b0 and 0x7b4 and the row count at 0x7b8. For each row it computes the evaluation parameter as row times the step plus the origin, using the stored end value exactly on the last row, so the mesh ends on the grid's end value without rounding drift. It works in column blocks of at most 256 (0x100) points, stepping the starting column by 0x100 in point mode (0x1b00) and by 0xff in line mode (0x1b01) so that adjacent blocks share one column. Each row is evaluated by the local `FUN_0d97c490` into one of two 16 KB stack buffers that alternate, and drawing goes through the per-context begin and end entries at offsets +0x1c and +0x2c of the table at context offset 0x17f4: begin 0 for points, begin 3 (line strip) for the row lines, and begin 1 (lines) for the cross lines drawn between the previous and current row by the local `FUN_0d97c850`.

## Evaluator support

- `changebasis` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd979e70, 6860 bytes, `kon_eval.c`):
  **Inferred.** Rewrites one polynomial curve from its Bezier control values into a second set of coefficients. The arguments are the input values, the order (control point count), the output and the element stride; the same three-word stride applies to every component. The first output is always the first control value. The order, below 16, indexes a jump table of unrolled cases (the 6.5.30m decompiler of the repository could not recover it, so it was read through Ghidra with the jump-table script). The jump-table entries (at the constant page plus 0x480) send orders 0 and 1 to a bare return after that copy and order 2 to a case that copies the second value across. Order 3 produces the first value, the last value and 2 times the middle value minus the first and last. Order 4 produces the first value, the last value, 3 times the second minus 2 times the first and minus the last, and the first minus 3 times the second plus 3 times the third minus the last. Orders 5 to 15 follow the same form, order 15 producing fourteen further values and order 12 eleven, with integer weights that grow with the order (14, 12, 11, 9, 3, 2 and 88 appear among the double constants). The outputs are written first to a local array and then stored at the output stride.

## Texture sub-image copy and upload routines

- `__glkonim_CopyTexSubImage` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd971ec0, 1752 bytes, `kon_texture_api.c`):
  **Established.** The Kona glCopyTexSubImage worker behind the 1D, 2D and 3D entry points. Its nine arguments are the target, the level, the three offsets into the level, the source corner (x, y) and the source width and height (the ninth, on the stack). Inside a begin (the word at process address 0x1018 equal to 1) it raises 0x502 and returns. It sizes the source with `computeDestinationDims` and validates the call with `checkTexSubImage`, which returns the texture slot; a negative result ends the call with the error already raised. The texture object is the context word at 0x7bb0 plus 4 times the slot, the level record the pointer at object +124 plus 4 times the level, and the pipe handle the word at context +0x8aac. If `unmatchObjLevel` reports the level inconsistent, or the object word at +264 or +268 (chosen by whether +284 equals the level's parity) is zero, it only sets the level's bit in the mask at +48 and returns.
  Otherwise, when object flag 0x1000000 is set and the context mask at 0x7b90 has the slot's bit, it runs `updateTexBindID`. It then picks one of three paths. With flag 0x400000 set, or a level border (record +20) of zero, it takes the whole-level path. With a border, offsets that are not negative and a region that fits inside width, height and depth minus twice the border, it takes the interior path. Any other region takes the third path, which does not copy: when the level is marked in the mask at +40 and not in +48 it calls `allocLevelImage` and reads the level back with `getLevel` (16-bit values, type 0x1403, format from the table `rdbk_format2`), and it sets the +48 bit.
  The whole-level and interior paths first read the level back to the host when its bit is clear in the mask at +44, inside two `__glKonSetNoModeState` calls (state 2 with 0x60000000, then 0), using `subloadLevel` with the format words of `rdbk_format2`; the whole-level read starts at minus the border and spans the full record size, the interior read starts at 0 and spans the size less twice the border. The copy itself is a `subloadLevel` call with the pipe handle, object, level, the level's format word (+4), the three offsets, the checked width and height, a depth of 1 and a five-word request record (1, source width, source height, corner x, corner y). If the level's +48 bit is then set, it clears the bit, calls the function the pipe handle keeps at +12 on the level's host image pointer and zeroes the pointer. All three paths end by setting the level's bit in the masks at +40 and +44 and, for flag 0x1000000 with the slot's bit set in the mask at 0x7b90, calling the object's function pointer at +256 with the context address plus 0x7b90 and the object. **Inferred:** the copy writes the framebuffer region into texture memory directly and drops the host image, so the level exists only there afterwards.
- `__glKonGetTexParameter` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd969ba0, 1632 bytes, `kon_texture_api.c`):

  Object offsets by name (public enum names): 0x2800 magnification filter +360, 0x2801 minification filter +364, wrap S, T and R (0x2802, 0x2803, 0x8072) the three 2-bit fields of the byte at +401 (bits 0-1, 2-3, 4-5) mapped through the table `int_clamp_to_ext_clamp`, 0x8066 priority a float at +328, 0x8067 resident (1 when every level from the base level at +24 to the last level at +20 is set in the texture-memory mask at +40), 0x813a and 0x813b minimum and maximum level of detail, floats at +352 and +356, 0x813c and 0x813d base and maximum level +344 and +348, 0x809a detail level minus bits 21-23 of the word at +64, 0x809b detail mode +372, 0x809c and 0x80b0 the point count (word +8) of the detail and sharpen function records at +304 and +308, 0x80bf shadow ambient a float at +520, 0x8124 and 0x8125 dual and quad select +456 and +460, 0x8171 clip-map centre two values from the low 15 bits of +96 and +100, 0x8172 clip-map frame a float at +428, 0x8173 clip-map offset the low and high halves of +88, 0x8174 clip-map virtual depth three values from +440, +432 and +436, 0x8179 and 0x817a post-filter bias and scale four floats at +480 and +464, 0x818e, 0x818f and 0x8190 LOD bias S, T and R floats at +532, +536 and +540, 0x819a and 0x819b compare mode and operator, the unsigned words at +508 and +512, and 0x1004 border colour four floats at +384 (stored only for float output; the integer form returns 0 and stores nothing). - `__glkonim_GetMapiv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd980d00, 1572 bytes, `kon_eval.c`):
  **Established.** The Kona glGetMapiv: `a0` is the map target, `a1` the query and `a2` the output array. Inside a begin (the word at process address 0x1018 equal to 1) it raises 0x502; a target outside the lists below or a query other than 0xa00, 0xa01 and 0xa02 raises 0x500.   Query 0xa01 (order) writes the u order for a 1D map (context +0x2347c plus 0x34 times the target, negated as the dump shows) and the u and v orders for a 2D map. Query 0xa02 (domain) writes the u range for a 1D map and the u then v ranges for a 2D map, each rounded to the nearest integer, half away from zero (0.5 added to a positive value, taken from any other, then truncated); the 2D record holds an unused word between the u and v ranges. Query 0xa00 (coefficients) copies the control points: the stored array keeps each component's values together, and the loops write them back point by point, k components per point, with the same rounding (u loop inner, v loop outer for a 2D map).

# libGLcore: the state-query functions of `kon_get.c`

Read from the N32 build of the 6.5.30m library, `usr/gfx/arch/IP27KONA32/libGLcore.so` (the `IP35KONA32` copy is the same file), through the annotated assembly in [libglcore/asm/KONA/kon_get.s](../libglcore/asm/KONA/kon_get.s) and the decompiler output in [libglcore/decomp/KONA/kon_get.c](../libglcore/decomp/KONA/kon_get.c). Where the two disagree the assembly rules: the decompiler scales every pointer offset by the element size of the pointer it guessed, and the assembly adds plain bytes. Addresses are virtual addresses in the library. `ctx` is the pointer held in the process word 0x1010 and the command port is process address 0x4000, as in the notation of [opengl.md](opengl.md). An entry says **Established** only for a function read whole.

Every query that needs the pipe's answer follows one pattern. The caller stores a request token and its arguments to the command port, calls `__glkona_wait_rdata`, and then reads the reply from the return-data buffer whose pointer is in `ctx` at +31588 (0x7b64). The reply starts 8 bytes into that buffer.

## Request, wait and reply

- `kona_get_offset` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd9586c0, 256 bytes):
  **Established.** Maps a `glGet` parameter name to a dense index for the value tables, and returns -1 for a name outside the supported ranges. If the word at process address 0x1018 equals 1 it calls `__glSetError` with 0x502 (invalid operation) and returns -1. Otherwise the ranges 0xb00-0xdf4, 0x2a00-0x2a02, 0x3000-0x3005, 0x4000-0x4007, 0x6000 and 0x8005-0x81c8 return the name minus 0xb00, 0x270b, 0x2d08, 0x3d02, 0x5cfa and 0x7cfe, so the indices run on from 0 to 0x2f4, 757-759, 760-765, 766-773, 774 and 775-1226 with no gap. Any other name calls `__glSetError` with 0x500 (invalid enumeration) and returns -1.
- `__glkona_wait_rdata` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd9587c0, 504 bytes):
  **Established.** Waits until the pipe has filled the return-data buffer, which it detects when the first word of the buffer at `ctx` +31588 becomes non-zero, and then clears that word and returns. It first reads one word at 0x1100 and discards it. It spins up to 200000 times (0x30d40) on the word, then calls `sginap` with 0 up to the same count, and then enters a third phase that calls `_sysconf` with 3, doubles the result and divides it by 100 (a multiply by 0xa3d70a3e and a shift) to pick the tick count of each `sginap` call. After 3000 passes of that phase it calls `__glKon_ioctl` with request 10017 (0x2721), prints the first 64 words of the buffer to standard error eight to a line with `fprintf`, and keeps waiting. The wait also ends when `sginap` returns non-zero in the second or third phase, which is how a signal cuts it short; every exit clears the first word of the buffer.
- `kona_get` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd9589c0, 60 bytes):
  **Established.** Asks the pipe for the value of one state variable: it stores the token 76 (0x4c) and then its argument to the command port, calls `__glkona_wait_rdata`, and returns the address of the reply, which is the return-data pointer from `ctx` +31588 plus 8.
- `__glkon_get_special` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd958a00, 76 bytes):
  **Established.** The one-argument query: it stores its first argument (the request token) and its second argument to the command port, calls `__glkona_wait_rdata`, and returns the reply address, the return-data pointer plus 8. `kona_get_current`, `__glkonim_GetClipPlane`, `kona_get_raster` and `__glkonim_GetError` use it with tokens 59, 60, 61 and 62.
- `__glkon_get_special2` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd958a50, 80 bytes):
  **Established.** Same sequence as the one-argument query with a third word: three stores to the command port, then a call to `__glkona_wait_rdata` and a return of the reply address at the return-data pointer plus 8. The buffer pointer is loaded from `ctx` again after the wait, so the reply address is the one in force when the wait ends.
- `__glkon_get_special3` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd958aa0, 84 bytes):
  **Established.** The same request, wait and reply sequence with four words sent to the command port, and the reply address returned as the return-data pointer plus 8. The four words are its four register arguments, stored in order.
- `__glkon_get_special4` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd958b00, 88 bytes):
  **Established.** The same request, wait and reply sequence with five words sent to the command port (the largest request any of the helpers sends), then a call to `__glkona_wait_rdata` and a return of the return-data pointer plus 8.
- `kona_get_variable` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95ab30, 84 bytes):
  **Established.** Reads the pipe-side variable named by the constant 0x812a: it calls `kona_get` with that constant (its own first argument is ignored), stores the word at 4 bytes before the reply address (the first word of the return-data buffer plus 4) through its second argument, and returns the reply address.

## Reads that answer from host state

- `kona_get_current` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95a5a0, 204 bytes):
  **Established.** The current-state query. It sends request token 59 with argument 0 through `__glkon_get_special` and returns a pointer into the reply chosen by the parameter name: GL_CURRENT_COLOR (0xb00) at +0, GL_CURRENT_INDEX (0xb01) at +16, GL_CURRENT_TEXTURE_COORDS (0xb02) at +20, GL_CURRENT_NORMAL (0xb03) at +32 and GL_EDGE_FLAG (0xb43) at +48 bytes. Any other name returns a null pointer.
- `kona_get_raster` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95a670, 232 bytes):
  **Established.** The raster-position query. It sends request token 61 with argument 0 through `__glkon_get_special` and returns a pointer into the reply: GL_CURRENT_RASTER_POSITION (0xb04) at +0, GL_CURRENT_RASTER_DISTANCE (0xb05) at +16, GL_CURRENT_RASTER_COLOR (0xb06) at +20, GL_CURRENT_RASTER_INDEX (0xb07) at +36, GL_CURRENT_RASTER_TEXTURE_COORDS (0xb08) at +52 and GL_CURRENT_RASTER_POSITION_VALID (0xb09) at +56 bytes, and a null pointer for any other name.
- `kona_get_evaluator` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd95a760, 168 bytes):
  **Established.** Answers the four evaluator-grid queries from the host copy of the state, with no command-port store and no wait. It writes into the return-data buffer from `ctx` +31588 at +8 and returns that address: GL_MAP1_GRID_DOMAIN (0xdd0) copies the floats at `ctx` +1932 and +1936 to +8 and +12, GL_MAP1_GRID_SEGMENTS (0xdd1) converts the integer at +1944 to float at +8, GL_MAP2_GRID_DOMAIN (0xdd2) copies the floats at +1948, +1952, +1964 and +1968 to +8, +12, +16 and +20, and GL_MAP2_GRID_SEGMENTS (0xdd3) converts the integers at +1960 and +1976 to floats at +8 and +12. Any other name leaves the buffer untouched.
- `__glkonim_GetError` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959560, 108 bytes):
  **Established.** The immediate-mode glGetError. If the word at process address 0x1018 equals 1 it calls `__glSetError` with 0x502 (invalid operation) and returns 0. Otherwise it calls `__glkon_get_special` with token 62 (0x3e) and the filler word 0xdbdbdbdb and returns the first word of the reply, so the error flag is held by the pipe side and read back.
- `__glkonim_GetClipPlane` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959640, 196 bytes):
  **Established.** The immediate-mode glGetClipPlane. A word of 1 at process address 0x1018 gives `__glSetError` 0x502; a plane name whose distance above 0x3000 is not below the plane count at `ctx` +3600 gives 0x500. Otherwise it calls `__glkon_get_special` with token 60 and the plane name, and widens the four floats of the reply (offsets 0, 4, 8 and 12) to the four doubles of the caller's array at offsets 0, 8, 16 and 24.

## Client-array pointers, lights, materials and texture environment

- `__glkonim_GetPointervEXT` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd958b60, 412 bytes):
  **Established.** The immediate-mode glGetPointerv. A word of 1 at process address 0x1018 gives `__glSetError` 0x502. Otherwise it stores one 32-bit pointer from `ctx` through the caller's pointer, chosen by the name: GL_VERTEX_ARRAY_POINTER (0x808e) from +5088 (0x13e0), GL_NORMAL_ARRAY_POINTER (0x808f) from +5116, GL_COLOR_ARRAY_POINTER (0x8090) from +5140, GL_INDEX_ARRAY_POINTER (0x8091) from +5168, GL_TEXTURE_COORD_ARRAY_POINTER (0x8092) from +5192, GL_EDGE_FLAG_ARRAY_POINTER (0x8093) from +5220, GL_FEEDBACK_BUFFER_POINTER (0xdf0) from +4872, GL_SELECTION_BUFFER_POINTER (0xdf3) from +4904 and GL_INSTRUMENT_BUFFER_POINTER_SGIX (0x8180) from +31608. Any other name calls `__glSetError` with 0x500. It sends nothing to the pipe.
- `__glkonim_GetLightfv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959710, 260 bytes):
  **Established.** The immediate-mode glGetLightfv. It calls `__glSetError` with 0x502 when the word at process address 0x1018 is 1, and with 0x500 when the light name minus 0x4000 is not below the light count at `ctx` +3588 or the parameter name is outside 0x1200-0x1209. Otherwise it calls `__glkon_get_special2` with token 65 (0x41), the zero-based light number and the parameter name. The word 4 bytes before the reply is the count of floats that follow, and the function copies that many floats unchanged to the caller's array.
- `__glkonim_GetLightiv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959820, 520 bytes):
  **Established.** The integer form of glGetLight, with the same checks as `__glkonim_GetLightfv` (0x502 under the 0x1018 flag, 0x500 for a light at or above the count at `ctx` +3588 or a name outside 0x1200-0x1209) and the same request through `__glkon_get_special2` with token 65. The reply floats are converted one at a time: for GL_AMBIENT, GL_DIFFUSE and GL_SPECULAR (names below 0x1203) each is multiplied by 2^32 (the constant 0x4f800000), halved and truncated, so the colour range maps onto the whole signed 32-bit range; for every other name the float is truncated to an integer unchanged.
- `__glkonim_GetMaterialfv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959a30, 288 bytes):
  **Established.** The immediate-mode glGetMaterialfv. A word of 1 at process address 0x1018 gives `__glSetError` 0x502. The face must be 0x404 or 0x405 (front or back) and the name 0x1200-0x1209 or 0x1600-0x1603, or `__glSetError` gets 0x500. It then calls `__glkon_get_special2` with token 70 (0x46), the face and the name, reads the count at 4 bytes before the reply and copies that many floats unchanged to the caller's array.
- `__glkonim_GetMaterialiv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959b50, 552 bytes):
  **Established.** The integer form of glGetMaterial: the same 0x502 flag check, the same face (0x404 or 0x405) and name (0x1200-0x1209 or 0x1600-0x1603) checks with 0x500 on failure, and the same request through `__glkon_get_special2` with token 70. The returned floats are scaled by 2^31 (multiplied by 2^32 and halved) and truncated for GL_AMBIENT, GL_DIFFUSE, GL_SPECULAR (0x1200-0x1202) and GL_EMISSION (0x1600); for the other names they are truncated unscaled.
- `do_gettexenv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959d80, 220 bytes):
  **Established.** Fetches a texture-environment parameter into an array of floats and returns 1 on success, 0 on error. The target must be GL_TEXTURE_ENV (0x2300) or it calls `__glSetError` with 0x500 and returns 0. It then calls `__glkon_get_special` with token 77 (0x4d) and the parameter name. GL_TEXTURE_ENV_MODE (0x2200) turns the first reply word, taken as an unsigned integer, into a float in element 0; GL_TEXTURE_ENV_COLOR (0x2201) and the name 0x80be copy the four reply floats unchanged; any other name gives `__glSetError` 0x500 and 0.
- `__glkonim_GetTexEnvfv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959e60, 88 bytes):
  **Established.** The immediate-mode glGetTexEnvfv: it calls `__glSetError` with 0x502 when the word at process address 0x1018 is 1, and otherwise calls `do_gettexenv` with the caller's three arguments and discards its result.
- `__glkonim_GetTexEnviv` (`usr/gfx/arch/IP27KONA32/libGLcore.so` 0xd959ec0, 296 bytes):
  **Established.** The integer form of glGetTexEnv. It calls `__glSetError` with 0x502 under the 0x1018 flag, otherwise calls `do_gettexenv` into a 16-byte float buffer on its stack and, when that returns non-zero, converts into the caller's integers: GL_TEXTURE_ENV_MODE (0x2200) truncates the one float, and GL_TEXTURE_ENV_COLOR (0x2201) and 0x80be scale all four floats by 2^31 (times 2^32, halved) and truncate. Other names write nothing.

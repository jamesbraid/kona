# Setup tools: one entry per function

Read from the 6.5.30m N32 programs `usr/gfx/setmon` and `usr/gfx/gfxinfo`, whose roles are in [setup-tools.md](setup-tools.md#setmon) and [install-tools.md](install-tools.md#setup-and-video-configuration-programs). Both link the board-family code of the older display-board family beside the Kona code; the entries below say which board family each routine speaks to where the code shows it. Addresses are file addresses of the build. GOT slots are numbered from the start of the global offset table, as in the other function chapters. A routine that sends an ioctl uses the descriptor given in its first argument or one of the globals `gfxfd` (GOT slot 373) and `ven_gfxfd`; the numbers are named in [kernel.md](kernel.md#private-ioctls).

## `setmon`

- `pipenumToString` (`usr/gfx/setmon` 0x1000bdb4, 144 bytes):
  **Established.** Asks the kernel for the board name of one pipe. `a0` is the pipe number and `a1` the caller's destination string. It builds a request in its own frame: the pipe number at sp+40, the address of the frame's first byte (a 40-byte reply area at sp+0) at sp+44 and the length 40 at sp+48; the other words of the 24-byte request are not written. It calls `ioctl` (global GOT slot 44) with the descriptor held in the global `gfxfd` (slot 373), the request 102 (`GFX_GETBOARDINFO`) and the request. A result of -1 calls `perror` (slot 45) with "setmon" (0x10042068) and returns 0. Any other result calls `strcpy` (slot 70) with the destination and the reply area plus 16, and returns 1.
- `vs2GetShadow` (`usr/gfx/setmon` 0x100140ec, 92 bytes):
  **Established.** Reads the display-board shadow block. `a0` is a connection record whose word at +16 is the graphics descriptor and `a1` the buffer. It calls `ioctl` (slot 44) with that descriptor, the request 10031 and the buffer. A result of -1 calls `perror` (slot 45) with "venice_loadsection_vs2_top(VENICE_VS2_GET_SHADOW ioctl)" (0x1003a9e0) and returns its result; otherwise it returns the ioctl result. The Kona driver has no slot for 10031 ([kernel.md](kernel.md#private-ioctls)), so on a Kona pipe this call fails.
- `vs2SetShadow` (`usr/gfx/setmon` 0x10014148, 104 bytes):
  **Established.** The write twin of `vs2GetShadow`: the same connection record in `a0` (descriptor at +16) and buffer in `a1`, `ioctl` (slot 44) with the request 10030. A result of -1 calls `syslog` (slot 130) with priority 2, the format "Failure in VENICE_VS2_SET_SHADOW ioctl in %s - %m" (0x1003aa18) and the string "vs2SetShadow()" (0x1003aa50) and returns its result; otherwise it returns the ioctl result.
- `KonWaitRData` (`usr/gfx/setmon` 0x100278e0, 264 bytes):
  **Established.** Waits for the pipe's return area to become valid. `a0` and `a1` are two strings for the error text, `a2` the address of the valid word (kept in `s2`) and `a3` a descriptor (kept at sp+24). It calls `sginap` (slot 57) with 1 and then reads the word at `a2`; a non-zero word returns at once, with that word in `v0`. Otherwise it polls the word in a loop: each pass adds 1 to a poll count in `s0`, and once the count passes 0x7ffff every further pass is followed by `sginap(1)` and a pass count in `s3`. When `s3` reaches 20001 it calls `fprintf` (slot 49) on the error stream (`__iob` plus 32) with "%s: [%s] return area did not go valid!\n" (0x1003c7c8) and `a0` and `a1`, then `ioctl` (slot 44) with the descriptor, the request 10017 (`KONA_CHECK_PIPE`) and a zero argument, clears both counts and keeps polling. A valid word ends the loop and returns with no defined result.
- `pipeCountOfSystem` (`usr/gfx/setmon` 0x100125a8, 200 bytes):
  **Established.** Counts the graphics boards. It calls `open` (slot 101) on "/dev/graphics" (0x1003a018) with flags 2050 (0x802). A negative result calls `fprintf` (slot 49) on the error stream (`__iob` plus 32) with "ERROR: couldn't open /dev/graphics.\n" (0x1003a028) and returns 0. Otherwise it calls `ioctl` (slot 44) with the new descriptor, the request 101 (`GFX_GETNUM_BOARDS`) and a zero argument. A negative result prints "ERROR: couldn't get number of boards.\n" (0x1003a050) the same way and returns 0 without closing the descriptor; otherwise it calls `close` (slot 104) and returns the ioctl result, the number of boards.
- `venice_get_dg2_eeprom` (`usr/gfx/setmon` 0x1000fa18, 268 bytes):
  **Established.** Reads the display-board EEPROM image into a caller buffer. `a0` is the buffer of 1798 words. It copies those 1798 words to the stack at sp+4, then calls `ioctl` (slot 44) with the descriptor read through the global `ven_gfxfd`, the request 10026 and the frame (the word at sp+0 receives a status). A result of -1 returns 0 with no message. A non-zero status calls `venice_grok_dg2_eeprom_error` (0x1000fcc4) with that status and returns 0. Otherwise it copies the 1798 words back from sp+4 to the caller's buffer and tests the word at buffer +12: 10 returns 1; any other value calls `printf` (slot 64) with "RealityEngine configuration eeprom contents obsolete; run setmon -x to fix.\n" (0x1003f028) and returns 0.
- `getVeniceInfo` (`usr/gfx/setmon` 0x10013184, 560 bytes):
  **Established.** Copies a RealityEngine display board's 936-byte information block to the caller. `a0` is the pipe number (`s0`) and `a1` the destination (saved at sp+56). It returns 0 with a message on the error stream when the global `ven_pipeMapped` is zero: `fprintf` to `__iob` plus 32 with "getVeniceInfo(): pipe not mapped, unable to probe for MCO.\n" (0x1003a420). Otherwise it calls `ioctl` with the descriptor behind the global `ven_gfxfd` and request 101 (`GFX_GETNUM_BOARDS`); a negative result logs "Unable to find number of graphics boards during %s initialization:  %m" (0x1003a460) through `syslog` with priority 2 and the string behind the global `vs2ProductName`, and returns -1. A pipe number greater than the board count logs "Invalid pipe number during %s initialization" (0x1003a4a8) and returns -1. It then asks for the board name with `ioctl` request 102 and a request of the pipe number, a reply pointer at sp+16 and the length 40; a result of -1 logs "graphics getboardinfo() failed during %s initialization:  %m" (0x1003a4d8) and returns -1. `strncmp` (slot 51) of the reply with "RE" (0x1004212c) for 2 bytes must be zero, otherwise it logs "Performing %s initialization on hardware not a RealityEngine" (0x1003a518) and returns -1. It calls `malloc` (slot 40) with the word at sp+52, the last word of the name reply; a null result logs "unable to malloc() for getboardinfo() during %s initialization" (0x1003a558) and returns -1. It repeats request 102 with the length 936 and the new buffer (a -1 result logs the getboardinfo message above and returns -1 without freeing), copies 234 words from the buffer to the caller's destination, calls `free` (slot 90) and returns 0.
- `venice_set_dg2_eeprom` (`usr/gfx/setmon` 0x1000fb24, 416 bytes):
  **Established.** Writes a display-board EEPROM image and checks it by reading it back. `a0` is the image of 1798 words (`s0`). It first fills in the header in place: the sum of the bytes from offset 16 to 7191 (7176 bytes, added by the loop at 0x1000fb60) goes into the word at +8, 10 into +12, 7192 into +4 and 17479 (0x4447) into +0. It copies the 1798 words to a frame at sp+4 and calls `ioctl` with the descriptor behind `ven_gfxfd`, request 10024 and the frame (the word at sp+0 is the status). A result of -1 prints "error in ioctl to write eeprom\n" (0x1003f078) with `fprintf` on `__iob` plus 32 and returns 0. A non-zero status calls `venice_grok_dg2_eeprom_error` (0x1000fcc4) and returns 0. Otherwise it clears 7192 bytes at sp+4 with `bzero` (slot 56) and calls `venice_get_dg2_eeprom` (0x1000fa18) on them; a zero result prints "error in ioctl to read eeprom\n" (0x1003f098) and returns 0. It then compares the 7192 bytes of the read-back image with `a0`, byte by byte; the first difference prints "error in comparison\n" (0x1003f0b8) and returns 0, and equal images return 1.
- `vs2_set_MasterGenlock` (`usr/gfx/setmon` 0x10015fe8, 860 bytes):
  **Established.** Programs the master-genlock part of a display board's two video channels. `a0` is the connection record (`s0`; the word at +16 is the descriptor), `a1` an enable flag (`s1`) and `a2` a second flag (`s2`). It reads the board's shadow block into sp+0 with `ioctl` request 10031; a result of -1 only calls `perror` (slot 45) with "vs2_set_MasterGenlock(VENICE_VS2_GET_SHADOW ioctl)" (0x1003ae88) and carries on with the stale frame. The shadow byte at sp+26 picks the channel: zero takes the first, non-zero the second. Each channel then has three cases. With `a1` and `a2` both non-zero it takes the shadow byte (sp+10 for the first channel, sp+21 for the second), calls `vs2RegisterSetBit` (0x10012c6c) with register 16416 (0x4020) and the mask 64 (first) or 128 (second), and uses the byte ORed with 0x40 as the value of register 8. With `a1` non-zero and `a2` zero it calls `vs2RegisterClearBit` (0x10012c04) with the same register and mask and the byte with 0x40 cleared. With `a1` zero it calls `venice_load_vs2_clockDivider` (0x10014f18) with the divider word from the frame (sp+28 or sp+32) and clears the same bit with `vs2RegisterClearBit`. All three then write the channel's block through `vs2WriteXilinxReg` (0x1001316c), base 16896 (0x4200) for the first channel and 16912 (0x4210) for the second, three registers in the order 0, 8, 10. With `a1` non-zero (the first two cases) register 0 gets the shadow byte at sp+5 (first channel) or sp+16 (second), register 8 the value formed above, and register 10 the byte at sp+12 (first) or sp+23 (second); with `a1` zero register 0 gets the byte at sp+4 or sp+15, register 8 the byte at sp+9 or sp+20, and register 10 the byte at sp+11 or sp+22. The register-10 byte is also stored in a global byte at gp-31118 (first channel) or gp-31117 (second), the store sitting in the delay slot of the register-10 write. After `sginap(11)` (slot 57) the register-10 write is repeated and the routine returns the last write's result.
- `venice_loadsection_vs2_top` (`usr/gfx/setmon` 0x100150c0, 1200 bytes):
  **Established.** Loads one video-input channel of a RealityEngine display board and mirrors it into the board's shadow block. `a0` is the connection record (`s2`), `a1` the channel's register base (`s1`: 16896, 0x4200, is channel 0, anything else channel 1), `a2` a flag (`s4`) and `a5` the parameter record (`s0`); `a3` and `a4` are not used. It calls `vs2WriteProgClock` (0x1001311c) with the record, the base and 20, then `sginap` (slot 57) with 2. It stores the low byte of the record word at +0 into a global byte (0x10041dc9 for channel 0, 0x10041dcb for channel 1), writes zero to the register 17088 (0x42c0) with `vs2WriteByte` (0x10013108), and when `a2` is non-zero calls `venice_load_vs2_clockDivider` (0x10014f18) with the record word at +4. It stores the low byte of the word at +8 into 0x10041dc8 (channel 0) or 0x10041dca (channel 1); when `a2` is zero it also sets bit 0x40 of the record word at +28. It prints the heading "vif parameters for mco channel 0:" (0x1003aaa0) or "channel 1" (0x1003aac8) and the record words at +12, +16, +20, +24, +28, +32, +36, +40, +56, +60 and +64 with `printf` (slot 64), one per line, under the names VIF_SYNC_WIDTH, VIF_HPHASE_LOOPGAIN, VIF_MCOUNTER, VIF_HORZ_LENGTH, VIF_GENSRC_CNTRL, VIF_BPORCH_CLAMP, VIF_FINE_PHASE_ADJ, VIF_MAGIC_HIGH, VIF_SYNC_WIDTH_INT, VIF_GENSRC_CNTRL_INT and VIF_BPORCH_CLAMP_INT (the strings from 0x1003aaf0 to 0x1003ac10), and stores the low byte of the word at +32 into 0x10041dd2 (channel 0) or 0x10041dd3 (channel 1). It then writes eight registers of the channel with `vs2WriteXilinxReg` (0x1001316c), at register offsets 0, 2, 4, 6, 8, 10, 12 and 14 in that order, the values being the low bytes of the record words at +12, +16, +20, +24, +28, +32, +36 and +40. The low bytes of the words at +56, +60 and +64 go to globals as well (0x10041dcc, 0x10041dcd, 0x10041dce for channel 0 and 0x10041dcf, 0x10041dd0, 0x10041dd1 for channel 1, in the order +56, +60, +64). Next it reads the shadow block into a frame at sp+0 with `ioctl` (slot 44) on the descriptor behind `ven_gfxfd`, request 10031, and a result of -1 only calls `perror` (slot 45) with "venice_loadsection_vs2_top(VENICE_VS2_GET_SHADOW ioctl)" (0x1003ac30). It overwrites the channel's part of the frame from the record and the globals (for channel 0 the bytes at sp+0, +1, +4 to +14, the flag byte at sp+36 set when bit 0x40 of the word at +28 is set, and the word at sp+28 from the record word at +4; for channel 1 the bytes at sp+2, +3, +15 to +25, the flag byte at sp+37 and the word at sp+32), sets the byte at sp+26 (channel 0: 0 when `a2` is non-zero and 1 otherwise; channel 1: 1 when `a2` is non-zero and 0 otherwise), and writes the frame back with `ioctl` request 10030; a result of -1 calls `perror` with "venice_loadsection_vs2_top(VENICE_VS2_SET_SHADOW ioctl)" (0x1003ac68). It always returns 0. Requests 10030 and 10031 have no slot in the Kona driver, so the shadow calls fail on a Kona pipe.

- `vs2setmon` (`usr/gfx/setmon` 0x1000bac8, 748 bytes):
  **Established.** Sets the video format of a RealityEngine display board and then loads the text-port format. `a0`, `a1`, `a2` and `a4` are passed on (saved at sp+1248, +1240, +1216 and +1224) and `a3` is a write-EEPROM flag (`s5`). With the flag set it calls `getuid` (slot 122); a non-zero user prints "setmon: must have root privilege to write eeprom\n" (0x10038ee8) with `fprintf` (slot 49) on `__iob` plus 32 and calls `exit` (slot 31) with -1. It calls `open` (slot 101) on "/dev/graphics" (0x10038c80) with flags 2050; a negative result prints "setmon: can't open /dev/graphics\n" (0x10038c90) and exits with 1. With the global word `pipenum` it then issues `ioctl` (slot 44) requests on the descriptor, each failure printing its own message and calling `exit` with 1: 102 with a request of the pipe number, a reply pointer at sp+16 and the length 936 ("setmon: graphics getboardinfo failed\n", 0x10038cb8); 113 with a zero argument ("setmon: can't set diag flag\n", 0x10038f20); 103 with the pipe number and the word 0x2000000 at sp+952 ("setmon: can't attach board\n", 0x10038ce0); and 110 with a zero argument ("setmon: can't map graphics\n", 0x10038d00). It calls `venice_set_pipeaddr` (0x1000fefc) with the reply area, the descriptor, 0x2000000 and the pipe number, and `vs2GeneratePath` (0x10012670) with the global buffer at 0x10042900, `a1`, `a0` and the pipe number. When the global `verboseFlag` is non-zero it prints "VS2 VOF path %s\n" (0x10038f40) and the path. It then calls `vs2Setmon` (0x10012d58) with the pipe number, the path, the verbose flag and the old values of the globals `genlockFlag` and `genlockTTL`, after zeroing `genlockTTL` and (in the call's delay slot) setting `genlockFlag` to 1. Finally it copies the path into a buffer at sp+960, appends "dg2_textportvof.u" (0x10038f58) with `strcat` (slot 43), and returns the result of `vensetmon` (0x1000aea0) called with 0, that buffer, "RE" (0x10042060), the saved `a2`, the EEPROM flag, 1 and the saved `a4`.

- `ng1_setmon` (`usr/gfx/setmon` 0x1000f064, 1676 bytes):
  **Established.** Loads a monitor timing file for a Kona pipe through the X video-control extension. `a0` is the graphics descriptor (`s1`), `a1` a board record (`s7`) with a byte at +16 (a flag), +40 (a level) and +64, `a2` the file name (`s5`) and `a4` a verbose flag (`s2`); `a3` is not used. A level byte of 3 or more selects the suffix "_r3.u" (0x10042108), and "_r4.u" (0x10042100) when the level is at least 4 and the byte at +64 is at least 11; when the name does not already contain the suffix (`strstr`, slot 102) it must be shorter than 91 characters (else it prints "setmon:filename %s too long\n" (0x10039d60) with `printf` (slot 64) and returns -1) and is rebuilt in a buffer at sp+0 from `bzero` (slot 56), the name minus its last two characters (`strncpy`, slot 80) and the suffix (`strcat`, slot 43). With the verbose flag set it prints "ng1_setmon: Loading monitor timing from %s\n" (0x10039d80). It opens the file with `fopen` (slot 82) and "r"; a failure prints "setmon: Couldn't find file %s\n" (0x10039db0), logs the name through `syslog` (slot 130, priority 2) and returns -1. It reads the first line (`fgets`, up to 4095 characters, newline removed with `strchr`, slot 50), and when there is one `sscanf` (slot 59) takes three hexadecimal numbers with "%x,%x,%x" (0x10039dd0) and keeps them as the platform-parameter record at sp+4216: a word, then two halfwords at +4 and +6 (the second and third numbers); with no line the record is left unset. It closes the file and calls `ioctl` (slot 44) request 101 for the board count; a negative result logs "can't get number of graphics boards" (0x10039de0) and exits with 1 (`exit`, slot 31). When the global `framelockFlag` is set the global `framelockArg` must be 118 ('v') or 103 ('g'), otherwise it prints "setmon: use -F v|g, not %c\n" (0x10039e08) on `__iob` plus 32 and exits with 1; the record word gets bit 0x8, and also 0x10 for 'g'. When the global `MSsyncFlag` is set `MSsyncArg` must be 109 ('m') or 115 ('s') (else "setmon: use -c m|s, not %c\n", 0x10039e28, and exit 1). For 's' it sets bit 0x800 of the record word. For 'm' it walks every board number except the global `pipenum` and, for each that answers `ioctl` request 102 (a failure just skips the board), issues requests 104 (detach), 112 (reattach with the board number and 0x2000000), 110 (map), 21012 (0x5214, with the board query block) and 104 again, each failure printing its own message ("graphics detach failed\n", 0x10039e48; "graphics attach failed\n", 0x10039b98; "setmon: can't map graphics\n", 0x10039e60; "Couldn't set slave sync\n", 0x10039e80) and exiting with 1; after the walk it reattaches and maps its own pipe (requests 112 and 110, same messages) and sets bit 0x400 of the record word. It then takes the last "/"-separated part of the file name (`strtok`, slot 94, with the delimiter string at 0x10042110), cuts it at the first "." and calls `XSGIvcSetPlatformParameter` (slot 79) with the global display and screen (`dpy`, `screen`), 0, 1, the record word's address and 4, and `XSGIvcLoadVideoFormatByName` (slot 84) with the display, screen, 0 and that name; a result other than 1 prints "XSGIvcLoadVideoFormatByName failed....\n" (0x10039ea0) and exits with 1. After `XSync` (slot 75) with 1, a non-zero byte at board record +16 sends a second `XSGIvcSetPlatformParameter` with flag 0 and a 12-byte block made of the record word and its two halfwords sign-extended to words, followed by another `XSync`. It returns 0.

- `vfmtActualHWToKonaTarget` (`usr/gfx/setmon` 0x100195a0, 1312 bytes):
  **Established.** The copy of the format-file target builder that `setmon` links, with a message routine (0x10018be0, not read here; it takes a format string and values) called at each step. `a0` is the pipe number (kept at sp+2020) and `a1` the target record (sp+2028). It keeps the descriptor in a local at sp+0 (initially -1) and the result at sp+4 (initially 0). It calls `vfmtMinimalKonaTarget` (0x10019540) on the target and `open` (slot 101) on "/dev/opengl" (0x1003cf58) with flags 2050, then `fcntl` (slot 150) with 2 and 5 and `ioctl` (slot 44) request 101 for the board count, kept at sp+8. Every failure after a message stores a code in the global word at gp-29628 and jumps to the common end: 441 for the open ("setupIO: open of %s failed: %s\n", 0x1003cf68, with `strerror`, slot 152), 447 for the count ("setupIO: GFX_GETNUM_BOARDS ioctl failed: %s\n", 0x1003cf98), 449 when the pipe number is above the count less one ("Pipe number %d does not exist\n", 0x1003cfe8), 456 for the board-information request ("Could not get basic board info for pipe %d\n", 0x1003d008), and 459 when the board name is not "KONA" (the message at 0x1003d038 names the board; the test is `strncmp`, slot 51, of the first 4 bytes of the reply against 0x10042200). The board-information request is 102 with the pipe number, a reply pointer at sp+16 and the length 1952, after `bzero` (slot 56) of that area. From the reply it reads: the word at reply +128 as the render-manager count, stored in target word +4 when it is 1, 2 or 4 (any other value prints the two messages at 0x1003d050 and 0x1003d078, both about a count defaulting to 1, and stores 1); the word at reply +180 as the pixel depth, stored in target word +8 when it is 0 to 3 (otherwise it prints the message at 0x1003d0a0, about a depth defaulting to small, and stores 0); the words at reply +108, +112, +116 and +120 copied to target words +16, +20, +24 and +28; and the word at reply +40 as the board-set number, stored in target word +0 as 0 for 0, 2 for 2, 3 for 6 and 1 for any other value. It prints "%d dg channels at rev %d, type #%d opt channel at rev %d\n" (0x1003d0d0) with the four copied words, and sets the result to 1. On every path it closes the descriptor with `close` (slot 104) when it is non-negative and returns the result (1 on success, 0 after a failure). The logic is the one described for `kona.so` in [opengl.md](opengl.md#vfmtactualhwtokonatarget); this copy differs in calling the message routine at each step.

## `gfxinfo`

`gfxinfo` links the same display-board routines as `setmon`. For the four routines below every instruction after the prologue was compared with the `setmon` copy, and the only differences are the global offset table slots and the string and global-variable addresses, which the entries give for this binary.

- `getVeniceInfo` (`usr/gfx/gfxinfo` 0x100188e0, 560 bytes):
  **Established.** The display-board information fetch, with the same flow as the `setmon` routine at 0x10013184: `a0` is the pipe number and `a1` the destination of the 234-word (936-byte) block. With the global `ven_pipeMapped` zero it prints "getVeniceInfo(): pipe not mapped, unable to probe for MCO.\n" (0x10023078) with `fprintf` (slot 66) on `__iob` plus 32 and returns 0. Otherwise it asks `ioctl` (slot 65) for the board count (request 101) and returns -1 through `syslog` (slot 64) with "Unable to find number of graphics boards during %s initialization:  %m" (0x100230b8) when that fails, or with "Invalid pipe number during %s initialization" (0x10023100) when the pipe number is above the count. The board-name request 102 uses a request of the pipe number, a reply pointer at sp+16 and length 40; failure logs "graphics getboardinfo() failed during %s initialization:  %m" (0x10023130) and returns -1. `strncmp` (slot 60) of the reply with "RE" (0x10027ebc) over 2 bytes must be zero, otherwise "Performing %s initialization on hardware not a RealityEngine" (0x10023170) is logged and -1 returned. `malloc` (slot 56) takes the last word of the name reply (sp+52); a null result logs "unable to malloc() for getboardinfo() during %s initialization" (0x100231b0) and returns -1. The second request 102 with length 936 fills that buffer (failure logs the getboardinfo message and returns -1 without freeing), 234 words are copied to the caller, `free` (slot 62) releases the buffer and the routine returns 0. The product name in each log line is the string behind the global `vs2ProductName`.
- `venice_get_dg2_eeprom` (`usr/gfx/gfxinfo` 0x1000f794, 268 bytes):
  **Established.** Reads the display-board EEPROM image of 1798 words into the caller's buffer through `ioctl` (slot 65) with the descriptor behind `ven_gfxfd`, request 10026 and a stack frame in which the word at sp+0 returns a status, exactly as the `setmon` routine at 0x1000fa18 does. A result of -1 returns 0; a non-zero status calls `venice_grok_dg2_eeprom_error` (0x1000fa40, slot 138) and returns 0; otherwise the image is copied back and the word at +12 must be 10 for a return of 1. Any other value prints "RealityEngine configuration eeprom contents obsolete; run setmon -x to fix.\n" (0x10024008) with `printf` (slot 59) and returns 0.
- `vs2GetShadow` (`usr/gfx/gfxinfo` 0x10019848, 92 bytes):
  **Established.** Reads the display board's shadow block with `ioctl` (slot 65) request 10031, the descriptor being the word at +16 of the connection record in `a0` and the buffer `a1`. A result of -1 calls `perror` (slot 47) with "venice_loadsection_vs2_top(VENICE_VS2_GET_SHADOW ioctl)" (0x10023638) and returns its result; otherwise it returns the ioctl result. It is the `setmon` routine at 0x100140ec.
- `venice_loadsection_vs2_top` (`usr/gfx/gfxinfo` 0x1001a81c, 1200 bytes):

- `kona_diagnose` (`usr/gfx/gfxinfo` 0x1000b1f8, 540 bytes):
  **Established.** Checks a Kona pipe's health word and runs the post-mortem program when it is bad. `a0` is the pipe descriptor (`s3`), `a2` the integer formatted into the pipe name with `sprintf` (slot 48) and "%d" (0x10027d58) at sp+0, and `a3` a verbose flag (kept at sp+168); `a1` is not used. - `main` (`usr/gfx/gfxinfo` 0x10005888, 2192 bytes):
  **Established.** The entry point shared by `gfxinfo` and `gfxinit`; it ends with `exit` and never returns. It keeps `argc` in `s2` and `argv` in `s5` and stores `argv[0]` in a global word at gp-31348. It takes the part of `argv[0]` after its last `/` (`strrchr`, slot 79) and compares it with "gfxinfo" (0x100279c0) and then "gfxinit" (0x100279c8): `s3` is 1 for the first and 0 otherwise, and a name that matches neither prints "%s: I don't know who I am.\n" (0x10020000) on `__iob` plus 32 and goes on as `gfxinit`. It sets a path buffer at 0x10027f28: `getenv` (slot 61) of "GL_GRROOT" (0x10020020) copied with `strcpy` (slot 43), or an empty string when it is unset, then "/usr/gfx/ucode/" (0x10020030) appended with `strcat`. A set `GFXINIT_DIAG` (0x10020040) whose first five characters equal "FALSE" (`strncasecmp`, 0x100279d8) clears the global word at gp-31228. In `gfxinfo` mode `getopt` with "v" counts -v in the global `verbose` and prints "usage: %s [-v]\n" (0x10020050) for any other option. In `gfxinit` mode it walks `argv[1]` onward by hand: "-c" sets the global word at gp-31332; "-d" copies the next argument into the path buffer; "-v" counts into `verbose`; "-f" sets `fifoopt` and reads the next three arguments with `sscanf` and "%i" (0x10027a00) into `fifo_pgib`, `fifo_taib` and `fifo_pgta`; "-boards" keeps a copy of the next argument (`strdup`) and ends the scan; an argument beginning with ":" is skipped and any other prints "usage: %s [-v] [-d <dir>] [-c]\n" (0x10020060) and the scan goes on. It calls `openlog` (slot 81) with "gfxinit" (0x100279c8), 32 and 24, `open` (slot 45) on "/dev/opengl" (0x10020080) with flags 2050 (a failure prints it with `perror`, logs "open of %s failed" (0x10020090) at priority 2 and exits with 1), and `fcntl` (slot 82) with 2 and 5 (a failure logs "fcntl of %s failed" (0x100200a8) and exits with 1). `ioctl` (slot 65) request 101 gives the board count, kept in the global word at gp-31344 (a negative result prints `argv[0]` with `perror`, logs "can't get number of graphics boards" (0x100200c0) and exits with 1; a count of 0 with `verbose` set logs "no graphics boards\n" (0x100200e8) and goes on). With a -boards list it allocates 4 times the count in words filled with -1 (`malloc` slot 56; failure logs "malloc failed for use_boards[]" (0x10020100) and exits with 1) and splits the list at commas with `strtok` (slot 57): each token must be all digits (the `__libc_attr` table bit 4), is turned into a number with `strtol` (slot 46, base 10) and stored; a number at or above the board count logs "skipping selected board %d (does not exist)\n" (0x10020120) at priority 4 and is dropped; more tokens than boards or any non-digit logs "unreasonable board select (-b) options" (0x10020150) at priority 3 and exits with 1. The number of boards to handle (the selected count, or the board count without a list) goes in the global word at gp-31340; when it is at least 2 it allocates an array of that many words for child process ids (gp-31324) and clears it, and it always allocates and clears a 40-byte record (gp-31328; failures log "malloc failed" (0x10020178) and exit with 1). It then visits board numbers from 0 to the count less one, skipping those not in the list, calling the file-local routine at 0x10006118 for `gfxinfo` and the one at 0x100063d0 for `gfxinit` with the board number (neither routine is read here). Afterwards, when the global word at gp-31320 is positive, it calls `waitpid` (slot 63) for each stored process id with the address of a status word in `main`'s frame: -1 prints `argv[0]` with `perror` and logs "graphics initialization failed" (0x10020188) at priority 2, and a non-zero exit code in the second byte makes the final status 1. It frees the 40-byte record, closes the descriptor kept at gp-31336, calls `closelog` and `exit` with the final status.

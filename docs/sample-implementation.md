# Public-source code in libGLcore

Much of `libGLcore.so` is not board code. The software renderer, the display-list machinery, the pixel paths and the name tables descend from the OpenGL sample implementation that SGI published, which this repository carries as the `ogl-sample` submodule. This chapter gives each such routine of the 6.5.30m N32 library its own entry: what it does, the public source file that holds the same routine, and whether it reaches the board. The board-specific routines (the `kon` and `KONA` prefixes, and anything that stores to a board window) are in [libglcore-functions.md](libglcore-functions.md) and [opengl.md](opengl.md).

Public source: the sample implementation under `ogl-sample/gfx/lib/opengl`. Paths in the entries are relative to `ogl-sample`. The shipped source file of a routine is the heading it sits under, for example `so_names.c`; the sample file that holds the same routine is named in the entry.

Labels follow [AGENTS.md](../AGENTS.md). An entry is **Established** only where the whole routine was read against the public body. **Inferred** entries are matched to the public routine by its name, its direct calls and its size, and were not read end to end. Where an entry says it differs from the public body, the difference was read in the disassembly. Each routine has an entry for the N32 library of the IP27 Kona build (`usr/gfx/arch/IP27KONA32`), which the IP35 copy repeats byte for byte. Where the 64-bit or original 32-bit build of the same routine makes the same number of calls and has a comparable size, it has its own entry at its own address, always inferred because only the N32 body was compared with the public source; those entries leave out routines whose description depends on structure offsets or sizes, which differ between the builds.

Direct calls that the disassembly labels with the name of a neighbouring symbol are calls to file-local routines.

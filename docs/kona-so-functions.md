# The Kona X module: one entry per function

## Drawing hooks, caches, cursor and resource-manager client

Read from the 6.5.30m `usr/lib/X11/dyDDX/kona.so`, the module of the IP19 host. The IP27 kernel names the pipe KONAL and the server loads `konal.so`, which has the same function names; most of its functions are the same code relocated to another base, but its pipe writers store each command's token number as a word at FIFO offset 0 followed by the payload, so these entries describe `kona.so` only and the konal.so builds are in [kona-ddx.md](kona-ddx.md#konalso-functions-below-the-split). The reading was done through the per-module assembly in [ddx/asm/kona/](../ddx/asm/kona/), with the callee names resolved through the module's global offset table. Addresses are virtual addresses in the module. The module's drawing commands are described in [opengl.md](opengl.md#x-server-module-drawing-commands); these entries cover the wrappers and hooks around them.

- `konCopyClip` (`kona.so` 0x439260, 160 bytes): **Established.** The X graphics-context copy-clip wrapper: it puts back the original function table the module saved in the context's private record (+164) over the context's own (gc +68), calls the original entry at +24, then reinstalls the module's table (the one in its read-only data). It writes no register.
- `konStereoPolySegment` (`kona.so` 0x441600, 888 bytes): **Established.** Stereo version of the X
  PolySegment operation (entry at +28 of the graphics-context operations table): it draws the request once for each eye. It swaps the context's operations table for the stereo-free one saved in its private record (+92), and when the screen record's stereo word (+220) is 1 it selects each eye's draw-buffer word of the private record (+96 for the first pass, +100 for the second), moves the drawable's y position and the private y offset by the eye offset (the halfword at +226 of the screen record) and revalidates the context with `konValidateWindowGC` (mask 8192) before calling the saved operation, then restores the position, the buffer word and the original table. It first copies the caller's request list with `Xalloc` and frees the copy afterwards. It writes no register itself; the drawing commands come from the operation it calls.

# Ghidra tooling

Everything that runs inside Ghidra lives here. Each component has its own
acceptance test; run them from the repository root, inside the Ghidra image,
with `root/` populated ([IRIX_FILES.md](../IRIX_FILES.md)). The checkers need
only Python 3 and run in the ordinary toolchain image. The comparison of Ghidra
with the assembly-to-C pipeline, and the failure modes of both, are in
[docs/tooling.md](../docs/tooling.md).

```
ghidra/
  processors/<name>/   one Ghidra processor extension per directory
  import/<name>/       loader and import scripts for firmware images
  types/<name>/        data-type scripts
  scripts/             the shared IRIX scripts, byte-identical across workspaces
```

## Build and run

Run a component's `tests/run-ghidra.sh` in the Ghidra image, then its
`tests/check.py` on the dump directory it writes:

```sh
re-run --workspace . --ghidra -- ghidra/processors/kona-ge/tests/run-ghidra.sh .cache/kona-ge
re-run --workspace . -- python3 ghidra/processors/kona-ge/tests/check.py .cache/kona-ge
```

(`re-run` mounts the workspace at `/work`, the Ghidra image with `--ghidra` and
the toolchain image without.) `run-ghidra.sh` installs a processor as a user
extension in a throwaway settings directory, so nothing is added to a Ghidra
installation. The Sleigh compiler output (`*.sla`) is not committed.

## Components

| Path | What it is |
|---|---|
| [processors/kona-ge/](processors/kona-ge/) | the geometry-engine microcode processor (`KONA-GE`), generated by `tools/gen_slaspec.py`, with the import script `KonaGEImport.java` |
| [processors/kona-ged/](processors/kona-ged/) | the distributor program processor (`KONA-GED`) and its import script |
| [import/kona-arm/](import/kona-arm/) | importer for the host-interface ARM firmware images: memory blocks, symbols, handler tables (`tables.tsv`) |
| [types/kona-types/](types/kona-types/) | `KonaTypes.java`: the ARM state block and vertex record structures, applied where their address is fixed |
| [scripts/](scripts/) | the IRIX MIPS scripts: `IrixGp`, `IrixJumpTables`, `FindWindowStores`, `DumpCallEdges`, `DecompileFunctions`, `ApplyStruct`; each states its use in its opening comment |
